# UI デザイン言語

構想は `concept.md`（特に §1.3, §3, §7, §14）。この文書は UI 実装者（React + Tailwind v4 + Radix + motion + cmdk）が従う具体仕様。数値はすべて決定値で、変えるときは同じコミットでここを直す。迷ったら §1 の原則に戻る。

> 画面は会話の木を中心に作り直し中（`docs/snapshot/20261030_ui-redesign-spec.md`）。骨組み（3 つの画面・タイトルバー・会話の状態の語彙・キーボード・通知）は §2.4a・§4・§5・§7.2・§8.5 に反映済み。ホーム・サイドバー・会話・成果物などの各画面の節は、各トラックが入るときに書き換える。

---

## 1. 原則

1. **注意は希少資源。** 色・動き・上位の配置は「人間の介入が必要なもの」に予約する。順調なものは静かに、ただし見ればわかる状態で置く。10 個動いていても画面がうるさくならないこと。権限も同じで、目指すのは「安全で、承認依頼 0」。エージェントの操作は事前に聞かず、あとから見えるようにする（§5.5）。
2. **速さは機能。** 入力から 16ms 以内に視覚的な反応、操作の完了感は 100ms 以内。楽観的更新を基本にし、待たせる箇所には理由を書く。アニメーションが操作を待たせてはいけない。
3. **キーボードが一級、マウスも等価。** すべての操作にキーボード経路があり、すべてのキーボード操作にマウス経路がある。ショートカットはボタンやメニューに常に併記して学べるようにする。
4. **動きは意味を運ぶときだけ。** 「状態が変わった」「場所が変わった」「どこから来たか」を伝える動きだけを使う。装飾目的の動きは入れない。
5. **静かな高密度。** 1 行に多くの情報を載せるが、階層は文字色の濃淡と余白でつけ、罫線と色面は最小限にする。長時間見ても疲れないこと。
6. **人と AI は同じ操作の主体として見せる。** AI が行った操作（セッション作成、Task 割り当て、承認要求）は人間の操作と同じ部品で表示し、主体（あなた / AI / システム）を常に小さく明示する。

## 2. デザイントークン

### 2.1 実装方針

- トークンは CSS 変数で `:root`（= dark、既定）と `[data-theme="light"]` に定義し、Tailwind v4 の `@theme inline` で utility に橋渡しする。コンポーネントは生の hex を書かない。
- テーマ設定は「ダーク（既定）/ ライト / システムに合わせる」。`<html data-theme>` を切り替える。切替時のトランジションはしない（全要素の色が補間されると重く、意味もない）。

```css
@theme inline {
  --color-app: var(--bg-app);
  --color-canvas: var(--bg-canvas);
  --color-surface: var(--bg-surface);
  --color-raised: var(--bg-raised);
  --color-hover: var(--bg-hover);
  --color-selected: var(--bg-selected);
  --color-fg: var(--text-primary);
  --color-fg-2: var(--text-secondary);
  --color-fg-3: var(--text-tertiary);
  --color-fg-4: var(--text-disabled);
  --color-line: var(--border-default);
  --color-line-subtle: var(--border-subtle);
  --color-line-strong: var(--border-strong);
  --color-accent: var(--accent);
  /* status は --color-st-running など同様に橋渡し */
}
```

### 2.4 状態色（Run / Task）

色だけに頼らず、必ず §2.5 のアイコン形状とラベルを併用する。各状態は `fg`（アイコン・ラベル）、`bg`（薄い面）、`border`（左バー・枠）の 3 つを持つ。`bg` と `border` は派生させる：

```css
--st-running-bg: color-mix(in oklch, var(--st-running) 14%, transparent);
--st-running-border: color-mix(in oklch, var(--st-running) 40%, transparent);
```

| 状態キー | 意味 | dark | light | 注意を引くか |
|---|---|---|---|---|
| `running` | 実行中 | `#3FA0F2` | `#1A6FC0` | 引かない（静かな脈動のみ） |
| `awaiting_approval` | 承認待ち | `#F0B232` | `#9A6400` | **引く**（要対応） |
| `failed` | 失敗 | `#F0565C` | `#C8303A` | **引く**（要対応） |
| `review` | 統合待ち・レビュー待ち | `#B07CF0` | `#8B55D6` | **引く**（要対応） |
| `interrupted` | 中断 | `#EE8540` | `#B4540F` | **引く**（要対応、ただし点滅させない） |
| `completed` | 完了 | `#43C17A` | `#17804A` | 引かない（一度だけハイライト） |
| `queued` | 待機中 | `#8A8F98` | `#6B7079` | 引かない |
| `cancelled` | 中止 | `var(--text-tertiary)` | 同左 | 引かない |

- ライトの値はすべて白地で 4.5:1 以上を狙った値。実装時にコントラストをテストで検証する。
- `--accent`（藍）は状態色に使わない。「操作できるもの」専用の色。
- エージェントごとに色を割り当てない（色は状態に予約）。識別はモノグラムと名前で行う。

### 2.4a 会話の状態（`SessionState`。`src/lib/states.ts` と `src/components/ui/` だけで定義）

会話・チップ・サイドバー・パレットは Run の状態ではなく、daemon が導出する会話の状態を出す。色だけでなく形でも区別し、ラベルはツールチップと読み上げに使う。

| state | トークン | dark | light | アイコン（lucide） | ラベル |
|---|---|---|---|---|---|
| `needs_you` | `--st-needs_you` | `#F0B232` | `#9A6400` | `Hand` | あなたの出番 |
| `failed` | `--st-failed` | `#F0565C` | `#C8303A` | `TriangleAlert` | 失敗 |
| `working` | `--st-working` | `#3FA0F2` | `#1A6FC0` | 回る `LoaderCircle`（動きを減らす設定では太線の `Circle`） | 作業中 |
| `supervising` | `--st-supervising` | `#A083F2` | `#7650D0` | `Diamond`（ゆっくり明滅） | 子の作業待ち |
| `queued` | `--st-queued` | `#8A8F98` | `#6B7079` | `CircleDashed` | 順番待ち |
| `review` | `--st-review` | `#B07CF0` | `#8B55D6` | `Eye` | 確認待ち |
| `stopped` | `--st-stopped` | `#8A8F98` | `#6B7079` | `CirclePause` | 停止中 |
| `done` | `--st-done` | `#43C17A` | `#17804A` | `CircleCheck` | 完了 |
| `idle` | `--st-idle` | `#5D616A` | `#A2A5AC` | `Circle` | 待機 |

- 並べ替え・集計の順は上の表の順（`STATE_ORDER`）。`needs_you` / `failed` のチップは枠を状態色にし、`needs_you` になった瞬間に 1 回だけ柔らかく光る（`acc-alarm-once`）。
- 共通部品：`StateIcon`、`SessionChip`（ホームのチップ・会話の子の列）、`AttentionRow`（出番 1 件を 1 行。答えは楽観的に消え、失敗したら戻してトースト）、`CostMeter`（80% 超で amber、上限で red）、`Elapsed`（作業中・待ちは `4分`、終わったものは `12分前`。毎秒の更新は作業中だけ）、`OutputIcon` / `RoleIcon` / `AttentionIcon` / `WorkspaceIcon`。各画面はこれを使い、作り直さない。
- 費用は `$0.21`（0.005 未満は `<$0.01`、0 は出さない）。推定かどうかはツールチップだけ。

### 2.9 フォーカス

- `:focus-visible` のみで表示（マウスクリックでは出さない）。
- 標準：`box-shadow: 0 0 0 2px var(--bg-canvas), 0 0 0 4px var(--focus-ring)`（2px オフセット）。
- 密なリスト内の行：外側リングではなく `inset 0 0 0 1px var(--focus-ring)` + `bg-selected`。
- 「キーボードで選択中の行」とタブフォーカスは区別する。選択中は `bg-selected` + 左端 2px の `--accent` バー。j/k の移動は選択の移動であり、フォーカスリングは出さない。

## 3. モーション

### 3.1 トークン

| トークン | 値 | 用途 |
|---|---|---|
| `--dur-instant` | 0ms | ホバーの出現、キーボードでの選択移動、送信したメッセージの表示 |
| `--dur-fast` | 120ms | ホバーの消失、色変化、ツールチップ、クロスフェード |
| `--dur-base` | 180ms | ポップオーバー、パネル開閉、ブロック展開、トースト |
| `--dur-slow` | 280ms | レイアウト移動（要対応ゾーンへの移動など） |
| `--dur-sweep` | 900ms | 完了ハイライト |
| `--dur-pulse` | 2000ms | 実行中の脈動ループ |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 出現・展開（既定） |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 消失 |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 往復・ループ |
| `spring.layout` | `{ type: "spring", stiffness: 500, damping: 40, mass: 1 }` | motion の `layout` 移動（減衰比 ≈0.9、オーバーシュートはほぼ見えない） |

規則：

- 消えるときは出るときの 0.7 倍の時間（例：出現 180ms → 消失 120ms）。
- **キーボード起点の移動・選択にはアニメーションを付けない。** j を押しっぱなしにしても遅れないこと。
- アニメーションは `transform` と `opacity` だけで行う。`width` / `height` / `top` を毎フレーム変えない（例外：ブロック展開の `height: auto`。展開対象は 1 つに限る）。
- 動作中のアニメーションは新しい操作で即座に打ち切れること（ユーザー操作を待たせない）。

### 3.2 イベント → 動き

| イベント | 動き | 意味 |
|---|---|---|
| `run.started`（queued → running） | 破線円 → 塗り丸に 180ms クロスフェード。以後、ドットから半径 1→2.2 倍・不透明度 0.5→0 のリングが 2000ms 周期で広がる（`ease-in-out`、ドットのみ、行は動かさない） | 「生きている」。目の端で気づける程度に留める |
| アクティビティ行の更新（`tool.called` など） | 旧テキストが 120ms で消え、新テキストが下から 4px 上がりつつ出る。1 行あたり最大 4 回/秒に間引く | 進捗していること。読ませるためではない |
| ストリーミング中のテキスト | 断片ごとのアニメーションはしない。末尾に 2px × 1em のキャレット（`text-tertiary`、1s 周期の点滅） | 生成中であること |
| `run.completed` | アイコンがチェックに変わる（scale 0.6→1、120ms）。行の左から右へ `--st-completed` 10% の帯が 1 回だけ走る（900ms）。1200ms 後に「完了」グループへ移動 | 「終わった」を 1 回だけ伝えて静かになる |
| `approval.requested` | 行が要対応ゾーンへ `spring.layout` で移動。左端に `--st-awaiting_approval` の 2px バーが 180ms で現れる。サイドバーとタイトルバーの件数が数字ロール（旧数字が上へ、新数字が下から、180ms） | 人間が気づくべき場所へ「やって来る」 |
| `run.failed` | アイコンが × に変わり、行の背景が `--st-failed` 8% から 0 へ 600ms で 1 回だけ退色。要対応ゾーンへ移動 | 異常を 1 回だけ知らせる。揺らさない・点滅させない |
| `run.interrupted` | アイコン変化のみ。デーモン再起動で複数件まとめて起きるため、個別の強調はせず、トーストを 1 件にまとめる | 静かな事実の通知 |
| 統合待ち（review）になった | 要対応ゾーンへ移動 + 左端バー（`--st-review`） | 人間の判断の順番が来た |
| 承認・拒否した | カードの操作部が 120ms で消え、「承認しました · 14:03」の 1 行に縮む（180ms）。行は元のグループへ `spring.layout` で戻る | 処理が手を離れたこと |
| 詳細パネルを開く・閉じる | パネルの幅は即座に確保し、中身だけ x 方向 16px → 0 + 不透明度で 180ms（閉じるは 120ms）。幅のアニメーションはしない | 選択したものの詳細が「横から出てくる」。本文のリフローを毎フレーム起こさない |
| モード切替 | 120ms のクロスフェードのみ。スライドしない | モードは並列の視点で、前後関係がない |
| 一覧 → Focus（Enter） | Focus 画面が y 4px → 0 + 不透明度で 180ms | 「中に入った」 |
| ツール呼び出しブロックの展開 | `height: auto` 180ms、中身は 40ms 遅れて 120ms でフェードイン | 折りたたみの開閉 |
| ダイアログ・パレット | scale 0.98 → 1 + 不透明度、140ms。閉じるは 100ms | 手前に来る |
| トースト | 右下から y 8px + 不透明度、180ms | 一時的な知らせ |

**並べ替えの保留**：ホームにポインターが乗っている間、またはキーボード選択から 2 秒以内は、並べ替えと折りたたみを保留する（最大 4 秒。§5.1）。手元の物が勝手に逃げないことを優先する。保留中も文字は出さない。選択は常にエンティティ ID に追従し、スクロール位置はアンカー要素で固定する。

### 3.3 `prefers-reduced-motion`

OS 設定に加え、アプリ設定「動きを減らす」（既定：システムに合わせる）を持つ。有効時：

- `transform` と `layout` のアニメーションはすべて即時。不透明度のフェードだけ 120ms 以下で残す。
- 脈動リングは静止したリング（2px、不透明度 0.4）にする。キャレットは点滅させない。
- 完了スイープは「1.5 秒間の静的な薄い面 → 120ms で消える」に置き換える。
- motion の `MotionConfig reducedMotion="user"` をルートに置き、独自 CSS アニメーションは `@media (prefers-reduced-motion: reduce)` と `[data-reduce-motion]` の両方で止める。

## 5. 3 つの画面

画面は ホーム（`mode: 'home'`、起動時はここ）、会話（`'session'`。`focusSessionId: null` は Ctrl+N の下書きで、最初の送信で会話を作る）、タイムライン（`'timeline'`）。旧 `'command'` / `'focus'` の保存値は ホーム / 会話 に読み替える。以下の 5.2 は作り直し前の記述で、会話（U3）が入るときに書き換える。

### 5.1 ホーム（`components/home/`）

アプリの顔。`home.get` 1 回＋イベントで描く。上から 出番 → 木のレーン → 入力欄。文字の説明は置かない。

```
┌ ホーム ──────────────────────────────────────────────────────────────────────┐
│ ⛨ [入力チェックを入れる] pnpm add zod を実行                     [許可 Y] [拒否 N] │ ← 出番（priority 順、0 件なら列ごと無い）
│ ? [FAQ を 10 問つくる] 価格を FAQ に載せてよいですか？  [載せる 1] [発売時に案内 2] [返信 Enter] │
│                                                                              │
│ ◆ ログイン改善                                   ▬▬▬▬▬▬▬▬            $0.66 ─ $3 │ ← 見出し：役割・題・状態の帯・次回・費用
│ ┌✋ 入力チェック…┐ ┌◉ エラー…  ┐ ┌◉ テスト…  ┐                                │ ← 子のチップ（状態の優先順）
│ ◇ ブログ記事 ⟳ 回答を作成中                                           <$0.01 │ ← 子のいない木：見出しだけ＋根の状態と now
│ ▢ 朝のまとめ                                     ▬▬▬▬▬▬▬▬   🕘 9:00    $0.07 │ ← 落ち着いた木：見出しだけ、文字を一段薄く
├──────────────────────────────────────────────────────────────────────────────┤
│ ◇ 何を頼みますか                                                    [▢][📁][⑂] │ ← 任せる・作業場所
└──────────────────────────────────────────────────────────────────────────────┘
```

- **出番の列**：`AttentionRow` を priority 順に。7 件以上なら 5 件＋「あと N 件」。新しい行は上から 180ms で入り、答えた行は 120ms で消えて詰まる。
- **見出し**：右端は固定幅の列（状態の帯 120px・次回・費用）で、レーンをまたいで縦にそろう。帯は `counts` を状態色で比例配分した 6px の棒（優先順に左から）。ホバーで状態アイコン＋数。根の状態は、子のいない木では題の横に（待機は出さない）、子のいる木では出番・失敗・作業中・順番待ち・停止のときだけ出す。
- **チップ**：`SessionChip md` のグリッド（`minmax(168px, 1fr)`）。`hiddenNodes` は末尾の「+N」（根の会話へ）。
- **落ち着いた木**（出番なし・done / idle / stopped だけ）は見出しだけ。題と役割アイコンを一段薄くし、続く落ち着いた木と詰めて並べる。
- **空のとき**：中央に入力欄 1 つと、その下に作業場所の切り替え（なし / フォルダ / コード）。
- **入力欄**：Enter で新しい会話を作って送り、ホームに留まる。Ctrl+Enter で作って開く。左の ◇（任せる）を押してから送ると、最初から任せた会話になる（create → delegate → send）。作業場所はフォルダ（`folderPath` のあるプロジェクト）かコード（リポジトリのプロジェクトの worktree）。候補が複数ならプロジェクト名のメニューで選ぶ。リポジトリが 1 つもないときの「コード」は「プロジェクトを追加」を開く。
- **保留**：ポインターがホームの上にある間、またはキー操作から 2 秒は、レーンの順・折りたたみ・チップの順を止める（最大 4 秒。§3.2）。カードの中身（状態・now・費用）は止めない。新しく来たレーンとチップは末尾に足す。保留が解けたら `spring.layout` で動く。
- **キーボード**：J / K（↓ / ↑）で 出番の行 → 各レーンの見出し → そのチップ の順に選ぶ（端で止まる。折りたたんだレーンは見出しだけ）。Enter で開く（出番は返信欄、返信できない出番は会話、見出しとチップは会話）。出番の行を選ぶとその行にフォーカスが移り、1〜4 / Y / N はその行が受ける。答えた行を選んでいたら、選択は次の出番へ移る。選択は画面外に出たらスクロールで追う。

- ヘッダー（44px）：状態アイコン、セッション名（クリックで改名）、モデル、worktree ブランチ、エージェントの Run なら判断の要約チップ（§5.5）、予算の使用/上限、主要操作（停止 / 再開 / 再試行は状態に応じて 1 つ）、`…`。
- メッセージ：
  - ユーザー：`bg-surface` + `border-default`、`radius-md`、padding 10px 14px。左寄せで本文と同じ幅（チャットアプリ風の右寄せ吹き出しにはしない。長文の指示が読みやすい）。
  - アシスタント：地の上にそのまま本文。発話者名は連続時は省略。
  - AI が送ったメッセージ（Orchestrator → Worker の指示など）は、ユーザーメッセージと同じ部品に「Orchestrator から」の小ラベルを付ける（原則 6）。
- **ツール呼び出しブロック**：既定は折りたたみ、1 行 32px（`radius-md`、`bg-surface`）。`▸ アイコン 動詞+対象  補足  所要時間`。連続するツール呼び出しは「ツール実行 N 件」に 1 つにまとめ、内訳を種類別に示す。失敗したツールは折りたたんだまま × アイコンと赤字の 1 行要約。ファイル編集は `+24 −6` を常に表示。展開で入力・出力（mono、最大 320px、超過は内部スクロール + 「全文を開く」）。
  - Core Daemon が記録した判断（`tool.decided`）は同じ行に静かに載せる。**ブロック**は盾のアイコン（`ShieldBan`）+ `ブロック` チップ（枠線のみ、色なし）+ 理由の 1 文（`text-fg-3`）+ 右端に判断者バッジ（`ルール` など）。失敗ではないので赤にしない（エージェントは理由を読んで続ける）。まとめた行では `失敗 N` と分けて `ブロック N` チップを出す。
  - 許可は右端に `自動で許可 · ルール` / `自動で許可 · Auto mode` / `記憶した許可`（`text-meta text-fg-3`、ツールチップで判断者の説明）。worktree 内の読み取り・編集のような日常の操作は記録されないので何も出ない。展開すると `判断` 欄に、判断者・プロファイル・理由の全文。
- **インライン承認カード**：会話の流れの中、要求が発生した位置に出る。`--st-awaiting_approval` の左バー、問いの形の見出し、対象（コマンド・ファイル・宛先）、影響範囲の 1 行、操作。影響範囲の行の末尾に**なぜ聞いているか**（`payload.reason` の 1 文。例 `テスト・ビルドはこのプロジェクトでは確認が必要`）を添える。承認は例外なので、理由のない承認カードは出さない。危険度が高い操作（worktree 外への書き込み、`git push`、削除系、ネットワーク送信）は承認ボタンを `--st-failed` の枠付きにし、`承認（要注意）`、キーは `Ctrl+Y`。承認カードが届いても自動でフォーカスを移さない（打鍵中の誤承認を防ぐ）。
  - **今後も許可**：ツールの承認には `承認 Y` `拒否 N` の右に ghost の `⟳ 今後も許可… A`。押すと操作部が範囲の選択に入れ替わる（120ms のクロスフェード）：`承認して、今後は確認しない範囲 [この Run 1] [この Task 2] [このプロジェクト 3] キャンセル` と、下に 1 文（デーモンが `payload.rememberAs` を返したら先頭に `覚える内容：コマンド「node scripts/test.js」を許可。`、続けて `同じ種類のコマンドを、選んだ範囲では確認なしで進めます。Core Daemon のルールで止める操作は対象外です。…`）。先頭の `この Run` にフォーカスが乗り、`Enter` でも決まる。Task のない Run では `この Task` を無効にして理由をツールチップに出す。危険度「高」と、ツール以外の承認（統合のテストなど）、デーモンが覚えられないとした承認（`rememberAs: null`。インラインのコードなど）には出さない。承認後の 1 行は、デーモンが実際に覚えた範囲を `承認しました · ⟳ このプロジェクトでは今後も許可 · 14:03` と言う。
- 右パネルのタブ：
  - **概要**：状態、Task、親（委譲元）、Capability（付与されている権限の要約と有効期限）、エージェントなら `ツール`（`おまかせ · Auto mode が判断` と `自動判断 12 件 · ブロック 1 件`、Auto mode を使わない理由があればその 1 文）、予算、worktree、関連 Run 履歴。
  - **変更**：ファイル一覧（+/−）→ 選択で unified diff（mono 12.5px、行番号 `text-tertiary`）。幅が足りないときは「大きく開く」でメイン領域に diff を広げる。
  - **テスト**：最新の結果（成功/失敗/スキップ件数）、失敗の一覧と先頭の出力。
  - **ログ**：その Run のイベント列（Timeline の部品を再利用）。
  - タブ切替は `[` / `]`（入力中以外）。未確認の更新があるタブ名に 6px のドット。

### 5.3 Timeline Mode（タイムライン）

```
┌ タイムライン   [種類 ▾] [主体 ▾] [プロジェクト ▾] [⌕ 絞り込み…]   [表示 ▾]  ● ライブ追従 ┐
│ 14:01:02  ◆ Orchestrator  判断   Task を 2 つに分割                                  │ ← accent 左バー
│           「認証と API は独立して進められるため並列にします」                          │
│ 14:01:03  ◆ Orchestrator  作成   Worker · 認証機能の改善（worktree acc/auth-…）       │
│ ▾ Run #a41  Worker · 認証機能の改善                       実行中 · 12:04 · $0.42     │ ← Run 見出し（sticky）
│ 14:01:05    ● 開始                                                                   │
│ 14:01:09    ⚙ 読み取り  src/auth/session.ts                                          │
│ 14:03:40    ? 承認を要求  pnpm test src/auth                                         │
│ 14:03:52    👤 あなた  承認                                                           │
│ 14:05:10    × テスト失敗  3 件                                                        │
│ ▸ Run #a42  Worker · テストの拡充（42 件）                完了 · 03:51 · $0.08       │
│ 14:09:30  ⚙ システム  予算   Orchestrator に $10 を割り当て                           │
│                                                                    [↓ 最新へ 12件]   │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

- TanStack Virtual で仮想化。行 28px（判断の理由など 2 行目がある行は 44px）。列は固定幅：時刻 `HH:mm:ss`（72px、tabular）、主体（アイコン + 名前、140px）、イベント（アイコン + ラベル、120px）、対象と要約（残り）。
- 新しいものが下。最下部にいる間は「ライブ追従」。上にスクロールすると追従を外し、`↓ 最新へ N件` ピルを出す。
- **Run でグループ化**（既定 ON）：Run 見出し行は sticky、状態・経過・コスト付き。終了した Run は既定で折りたたみ、実行中と要対応の Run は展開。
- **Orchestrator の判断**（`orchestrator.*` の判断イベント）は `--accent` の 2px 左バー + `判断` バッジ + 理由文を 2 行目に引用表示。「なぜこうなったか」をここで追える。
- フィルタ：種類（Run / ツール / 承認 / エラー / 統合 / 予算 / 権限）、主体（あなた / AI / システム）、プロジェクト、セッション、テキスト。フィルタは URL 状態に持ち、パレットからも設定できる。デスクトップにはアドレスバーがないので、フィルタと表示設定はローカルにも保存し、次回も同じ見え方で開く（URL に `tl.*` があればそちらが勝つ）。
- 行の選択で詳細パネルにイベントの全内容（JSON は折りたたみ表示）。Enter（または行のホバーで出る `会話を開く` / `Task を開く` / `統合を開く`）でその出来事の場所へ飛ぶ：メッセージは会話の該当位置へスクロールして 1 回だけ薄く光らせ、Task は Task ボードで選択、統合はレビュー画面。
- **ツールの判断**（`tool.decided`）：`ブロック`（盾のアイコン、左端に `border-strong` の 2px バー、2 行目に `理由: …`）、`自動で許可`、`記憶した許可` の行。要約の前に判断者のバッジ（`ルール` / `Auto mode` / `記憶` / `あなた`、枠線のみの `text-micro`）を置き、対象のコマンドは mono。「あなたに確認」は `承認を要求` の行が同じことを語るので既定では隠し、その 2 行目に理由を出す。種類フィルタの `権限` に入る。折りたたんだ Run の見出しは `（12 件 · ブロック 1）` とブロックの数を残す。
- **表示メニュー**（ヘッダー右、`表示 ▾`、オンの数を表示）：`自動許可も表示`（日常の自動許可も並べる。ブロックと確認はいつも出る）と `詳細なイベントも表示`。2 つのスイッチを並べるとパネルを開いた幅でヘッダーが折り返すので 1 つのメニューにまとめる。パレットからも切り替えられる。
- Run で絞り込んだとき（判断チップの `タイムラインで見る`）は、ヘッダーに `Run #a41 ×` のチップを出し、その Run は終わっていても展開して開く。
- **物語として読める既定表示**：配管のイベント（ロックの変化、使用量の刻み、成功したツールの結果、専用イベントと重複する状態変化、Run 作成）は既定で隠し、ヘッダーの `表示 ▾` の `詳細なイベントも表示` で出す。行は名前で語る（`「設計チャット」が作業を開始`、`Task を作成: 「…」`、`「task.spawnWorker」を試みましたが、許可されていないため止めました` + `理由: …`）。主体は同じ形のバッジ `あなた` / `AI`（+ 役割名）/ `システム` で示す。時刻の右に直前のイベントからの間隔（`+4.2s`、1 秒未満は出さない、1 分以上はやや濃く）を置き、待ち時間が図なしで見えるようにする。Capability で拒否した行（`policy.denied`、人間が権限を見直すきっかけ）は `--st-failed` の左バー。ツールのブロックは上のとおり色なし。

### 5.4 統合レビュー（concept §6、§12.1 の 7〜9）

統合カードの `レビューを開始`、Task ツリーの `統合: …` から開く。メイン領域を置き換える（モードではない）。`Esc` / `← 司令室` で戻る。

- ヘッダー（44px）：状態アイコン、統合のタイトル、状態バッジ、右端に `⑂ acc/integration-… → main`。
- 左列（320px）：**手順**（番号つき。マージ ×N → テスト → 反映。実行中の手順の下に細い不定プログレス、所要時間、詳細文、コンフリクトしたファイルの一覧）、**テスト結果**（成否・コマンド・出力の末尾。出力は末尾までスクロールした状態で開く）、**ファイル**一覧（クリックで右の該当ファイルへ）。
- 右：統合後の差分を全ファイル縦に並べる。ファイルごとに sticky な見出し（ディレクトリは `text-tertiary`、ファイル名は `text-primary`、`+/−`）で開閉。400 行を超えるファイルとバイナリは最初から畳む。`J` / `K` でファイル移動、`O` で開閉、`すべて展開 / すべて折りたたむ`。差分のない側の数（`+0` など）は `text-disabled` に落とす。
- 下部の判断バー（56px）：反映待ちなら `テスト成功 · 3 ファイル · main へ早送りで反映` と `却下`・`承認して反映`（`Ctrl+Enter`）。失敗なら理由と `再実行`。反映後は `main に反映しました · 14:03`（トーストは出さない：見ている場所の出来事なので）。マージが止まってテストを省いた試行のテスト結果は `マージが終わっていないため、テストはまだ実行していません。`（「テストコマンドがない」とは言わない）。
- **コンフリクト → Integrator**：コンフリクトなら理由と、主操作 `Integrator に解消を任せる`（`Ctrl+Enter`。`再実行` は同じところでまたぶつかるので ghost に下げる）。確認ダイアログは「何が起きるか」を言い切る：`「B」をマージするときに README.md がコンフリクトしました。` / `統合ブランチ … でこのマージをやり直し、Integrator（エージェント）が両方の Task の目標を踏まえて解消します。` / `解消できたらマージをコミットし、残りのマージとテストを続けます。main はまだ変更しません（反映にはあなたの承認が必要です）。`。任意の補足（`instructions`）を書ける。確定で `integration.resolveWithAgent`（楽観的に running、断られたら元へ）。解消中は手順に `fix` の行が増え（プログレス、デーモンの詳細文、Integrator の今の作業を 1 行、`Integrator の作業を開く`）、バーは `Integrator がコンフリクトを解消しています。終わると統合を再開してテストします` と `Integrator を開く`。結果は手順とバーにそのまま出る：解消できれば `fix` が完了して反映待ちへ（マージ行のファイル一覧は「コンフリクトしていた」記録として静かな色で残す）、できなければコンフリクトに戻り、理由と `もう一度 Integrator に任せる`。
- **統合後のテストの承認**（慎重プロファイルでエージェントが始めた統合だけ。おまかせ・標準では聞かない：Worker が同じコードを同じ権限で既に実行しているため）：レビューの `テスト結果` の下に承認カード（§5.2 と同じ部品、理由 `慎重プロファイルでは、エージェントが始めた統合のテストを実行する前に確認します`）を出し、その場で答えられるようにする。司令室の要対応カードにも同じものが出る。
- **承認して反映は人間だけ**。確認ダイアログは「何が起きるか」を言い切る：`「A」、「B」の変更（3 ファイル、+32 −0）を main に反映します。` / `統合ブランチ … の検証済みの状態まで、main を早送り（fast-forward）します（abc1234 → def5678）。新しいマージコミットは作りません。` / `各 Task の worktree とブランチはそのまま残ります。`。テストが成功していなければ注意の帯を添える。任意のメモは承認の記録に残る。
- 承認・却下は楽観的に即反映し、デーモンが拒否したら（反映先が進んだ等）元に戻して理由をトーストで出す。

### 5.5 権限と自動判断（安全で、承認依頼 0）

エージェントを安心して任せられるのは、聞かれるからではなく、壊せないから。安全は隔離（worktree）・Core Daemon のルール・main への反映の承認・あとから見える記録でつくり、承認は技術的な妥協として最後にだけ使う（architecture §2.10）。UI はこの順で見せる。

- **プロファイル**（プロジェクトの設定 / 設定の `エージェントの権限`）：ラジオの縦並び、各行に「確認なしで進むもの」を 1 文。並びは推奨順。プロジェクトでは先頭に `全体の既定に従う（おまかせ）`。下に盾のアイコンで、どのプロファイルでも変わらないこと（`push・worktree の外への書き込み・資格情報・.git の変更などは Core Daemon が止めます。main への反映は常にあなたが承認します。`）を 1 行。

  | プロファイル | 1 文 |
  |---|---|
  | おまかせ（推奨・既定） | worktree の中で完結する作業はすべて確認なしで進めます。決められないものは理由を添えて止め、あなたには聞きません。 |
  | 標準 | おまかせと同じですが、新しい依存の追加・worktree の外の読み取り・未知のツールはあなたに確認します。 |
  | 慎重 | 読み取り・編集・読み取りだけのコマンドだけを確認なしで進めます。ほかのコマンドと統合後のテストはあなたに確認します。 |

- **Auto mode**（設定）：オン / オフ、`判定する場所`（§5.5 と同じラジオ。`サーバーで判定（推奨）` — `Anthropic のサーバーで判定。追加のリクエストなし（上流が Anthropic API のとき）`／`手元の分類器` — `分類器モデルへ別リクエスト。1 回約 $0.01、キャッシュが冷えると約 $0.13`。下に `どちらも、このアプリ向けの追加ルールで判定します。Core Daemon の絶対ルールはその前に必ず適用されます。`。`judge` を返さない古いデーモンでは出さない）、LiteLLM 経由のときの分類器のモデル名（離れたときに保存。プレースホルダーは `LiteLLM で Claude Sonnet 5 を指すモデル名（例: claude-sonnet-5）`、既定のモデルは決め打ちしない。説明はサーバー判定なら「予備」、手元なら「空ならルール」）。判定できないときはルールで判断する、と説明文で言い切る。
- **見せ方の強さ**：ブロックは「目に入るが、驚かせない」。盾のアイコン・枠線のチップ・理由の 1 文までで、状態色・動き・要対応ゾーン・通知は使わない（人間の出番ではない）。自動の許可はさらに静か（右端の `text-fg-3` の注記、Timeline では `表示` メニューから）。人間の判断が本当に要るもの（承認、統合の反映）だけが §2.4 の注意色を使う。
- **判断の要約チップ**（Focus ヘッダー）：`🛡 自動判断 12 件 · ブロック 1 件`（確認があれば `· 確認 1 件`）。`text-meta text-fg-3`、ブロックがあれば盾の形だけ変える。押すとポップオーバー（380px）：`この Run の判断`（`おまかせ · Auto mode が判断（サーバー判定）` / `（手元の分類器）` / `ルールで判断`、プロファイルの 1 文、Auto mode を使わない理由）、`自動で許可 / ブロック / あなたに確認` の 3 つの数、`最近のブロック`（対象 mono、判断者、理由、`エージェントには理由を伝えてあり、別の方法で作業を続けます。`）、`タイムラインで見る`。
- **判断者の呼び名**（チャット・パネル・Timeline で共通。`model/permissions.ts` の `DECIDER`）：`ルール`（Core Daemon のルール）/ `Auto mode`（Claude Code の安全性の分類器。判定した場所が分かればツールチップに `（Anthropic のサーバーで判定）` / `（手元の分類器で判定）`）/ `記憶`（「今後も許可」で覚えた許可）/ `あなた` / `エージェント`。
- **記憶した許可**（プロジェクトの設定）：説明（`コマンド「pnpm add」を許可`）、範囲（`プロジェクト全体` / `Task「…」` / `その Run の間`）、いつ、`取り消す`（ghost、即時・楽観的）。0 件なら `まだありません。承認するときに「今後も許可」を選ぶと、ここに並びます。`。パレットの `プロジェクトの設定（権限・記憶した許可）…` から開ける。

## 6. チャットコンポーザー

- 自動伸長：1 行（44px）から 12 行まで。それ以上は内部スクロール。
- `Enter` 送信、`Shift+Enter` 改行、`Ctrl+Enter` も送信。**IME 変換中（`event.isComposing` または `keyCode === 229`）の Enter は送信しない。** 日本語入力での誤送信は最悪の手触りなので必ずテストする。
- 送信は楽観的：押した同じフレームでメッセージを一覧に追加し、入力欄を空にする。送信失敗時はメッセージに `送信できませんでした · 再送` を出し、本文を失わない。
- 空の入力欄で `↑`：直前の自分のメッセージを編集（未応答の場合のみ）。入力欄の上に `直前のメッセージを編集しています · 取り消す Esc` を出し、送信すると送り直す（元のメッセージが始めたチャットの Run が動いていれば止めてから送る。エージェントの Run は `↑` では止めない）。履歴は消さず、元のメッセージは `編集前:` の 1 行（取り消し線）に畳む。
- メッセージの操作は、ホバー / フォーカスでメッセージの右上に浮かぶ小さなバー（レイアウトを動かさない）：自分のメッセージは `コピー` と（編集できるとき）`編集して送り直す ↑`、アシスタントは `コピー` と（Run が失敗・停止・中断なら）`再試行`。長い自分のメッセージ（18 行 / 1,800 文字超）は畳んで `全文を表示（N 行）`。モデルの思考（reasoning）は `思考過程 · N 文字` の 1 行に畳む（生成中は `考えています…`）。コードブロックのコピーはホバーで出て、キーボードのフォーカスでも出る。
- 下書きはセッションごとに保持（切り替えても消えない）。
- ツールバー（入力欄の下段、28px）：モデルピッカー（チップ、`Ctrl+M`）、権限チップ（§6.2）、右端に `Enter 送信` のヒント。生成中は送信ボタンが停止ボタンに変わる。
- モデルピッカー：cmdk のポップオーバー。モデル名、提供元、相対コスト（`$` / `$$` / `$$$`）、最近使ったものが上。
- 行頭の `/` でスラッシュコマンド（`/model`、`/new`、`/orchestrate`、`/stop`）。`@` によるセッション・Task の参照は後のフェーズ（候補ポップオーバーの部品は cmdk を共有する設計にしておく）。
- 長いテキストの貼り付け（40 行超）は添付チップ `貼り付けたテキスト · 240行` にまとめ、クリックで中身を確認できる。

### 6.1 ストリーミング描画

- デルタは `requestAnimationFrame` 単位でまとめて反映する（10 本同時でも 1 フレーム 1 回）。
- Markdown はブロック単位で処理し、確定したブロックはメモ化して再描画しない。再パースするのは末尾の未確定ブロックのみ。
- 開いたままのコードフェンスは最初からコードブロックとして描画する（段落 → コードへの切り替わりによるガタつきを防ぐ）。シンタックスハイライトはブロックが閉じてから Web Worker で適用する。
- 表示中の領域より上でレイアウトが動かないこと。画像や埋め込みは事前に寸法を確保する。
- **自動スクロール**：最下部から 48px 以内にいる間は追従する。ユーザーが上方向にスクロール（ホイール・キー・スクロールバー）した時点で追従を解除し、`↓ 新しいメッセージ` ピル（コンポーザーの上、中央）を出す。最下部まで戻る、ピルを押す、自分が送信する、のいずれかで追従を再開する。プログラムによるスクロールで追従判定を誤らないよう、判定はユーザー入力イベント起点で行う。
- 生成停止：入力欄にフォーカスがあり、チャットが生成中なら `Esc` で停止（チャットのみ。エージェント Run は §7.2 の停止操作）。停止した応答は残し、`停止しました · 続きを生成` を末尾に出す。

### 6.2 Orchestrator 権限（「権限を与えるだけで Orchestrator になる」、concept §3.1）

アプリの象徴的な瞬間。権限は「何をどこまで任せたか」が一目でわかる形で、会話の中に残す。

- **権限チップ**（ツールバー、チャットのみ）：なし → `◇ Orchestrator 権限: なし`（`text-fg-3`、クリックで付与ダイアログ）。付与後 → accent 14% の面のチップ `◆ Orchestrator · Worker 2 · $5.00 · この実行のみ` と右端の `×`（その場で取り消し）。チップのクリックで詳細ポップオーバー（対象プロジェクト、Worker 上限、予算の上限 / 配分済み / 使用、できることの一覧、`統合の反映は常にあなたが承認します`、`設定を変える` / `権限を取り消す`）。付与の瞬間だけ accent のリングが 1 回広がる（900ms、`acc-grant-glow`、動きを減らす設定では出さない）。
- **付与ダイアログ**（640px、`/orchestrate`・パレットからも開く）：役割のプリセット 3 枚（`Orchestrator`（推奨）/ `計画のみ` / `すべての操作`）、対象プロジェクト、Worker 数（1〜8、ステッパー）、予算（`$1 / $5 / $20 / その他 / なし`）、有効期間（`この実行のみ` / `このセッション` + 期限 `1 時間 / 8 時間 / 24 時間 / 期限なし`）。下部に**結果を 1 文で言い切る**要約（`このチャットは「acme-web」で Task を分け、Worker を 2 人まで並列に起動できます。…次の実行が終わると自動で失効します。`）と、できることのチップ。`Ctrl+Enter` で付与。付与は楽観的（押した瞬間にチップが出る、失敗したら消えてトースト）。
- **会話の中の記録**：付与と終了（取り消し・実行の終了・期限切れ）は、チャットの時系列に中央寄せの細い区切り線として残す（`◆ あなたが「Orchestrator」の権限を付与しました · Worker 2 人まで · この実行のみ · 14:03`）。主体を必ず書く（原則 6）。
- **役割の表示**：Focus ヘッダーの役割表記が `チャット` → `◆ Orchestrator` にクロスフェード（180ms）。予算があれば `$0.42 / $5.00`。
- **まだ何も話していない Orchestrator チャット**は空白にせず、中央に役割の紹介を置く：`このチャットは Orchestrator です`、制約のチップ（Worker 数・予算・期間・対象）、流れ `目標 → Task に分割 → Worker が並列に作業 → 統合とテスト → あなたが承認`。

## 7. コマンドパレットとショートカット

### 7.1 コマンドパレット（`Ctrl+K`）

- 幅 640px、上端から 18vh、`radius-lg`、レベル 3。入力 48px、項目 36px、最大 9 項目表示。起動 50ms 以内。外枠だけを常に置き、中身（項目の一覧）は開いている間と閉じるフェードの間だけ描画する（閉じたまま中身を持つと、デーモンのイベントのたびに全項目を描き直すため。10 Run 同時開始の描画の約半分を占めていた）。
- 項目：アイコン、ラベル、補足（`text-tertiary`）、右端にショートカット（`Kbd`）。
- 入力が空のときのセクション：
  1. **提案**（文脈依存）：`次の要対応へ`（件数付き）、選択中の項目への操作（`承認` / `拒否` / `再試行` / `停止`）、`直前のセッションに戻る`。
  2. **移動**：セッション（最近順）、プロジェクト、モード。
  3. **作成**：`新しいチャット`、`新しいエージェントタスク`、`Orchestrator に依頼…`。
  4. **表示・設定**：`サイドバーを切替`、`詳細パネルを切替`、`テーマを切替`、`動きを減らす`、`設定を開く`、`ショートカット一覧`。
- 検索は英語名・日本語ラベル・読み（ローマ字）・別名を `keywords` に持たせてあいまい一致（例：承認 → `approve shounin yes`）。最近実行したコマンドを上位に。
- ネストページ（`モデルを変更 →`、`プロジェクトを切替 →`）。`Backspace`（入力が空のとき）で戻る。
- 一致がないときの最下段に `AI に頼む：「テスト担当をもう2人追加して」`。選ぶと権限を持つチャット（なければ新しいチャット）にその文を送る。GUI と自然言語が同じ機能に届く（concept §3.2）入口。
- 接頭辞：`>` コマンドのみ、`#` 会話の検索（セッション名 + メッセージ）、`?` ヘルプ。
- **メッセージ検索**：2 文字以上の入力（`>` / `?` 以外）で `session.search` を 180ms 遅らせて呼び、`メッセージ` の節にスニペット（検索語を `mark` で強調）・会話名・時刻を出す。選ぶと会話を開き、そのメッセージへスクロールして 1 回光らせる。打鍵は検索を待たない。
- 一致がないときは `AI に頼む` の上に `「◯◯」に一致するものはありません`（§8.2）。
- 提案には `次の承認待ちへ` と、最も古い承認待ちの `承認: <名前>`（補足に対象のコマンドを出す。危険度「高」はパレットから承認させず、カードの `Ctrl+Y` に任せる）も並べる。ほかに統合のレビュー、Task ボード、選択中の Task の実行・再開（中断した Task）・中止、Orchestrator 権限の付与・取り消し、テーマの直接切替、プロジェクト名での切替（検索中）、ピン留め・アーカイブ、通知の切替、タイムラインの詳細表示。

**`Esc` の優先順位**（上から順に、該当するものを 1 つだけ処理する）

1. パレット・メニュー・ポップオーバー・ダイアログを閉じる
2. インライン編集（改名など）を取り消す
3. チャット生成中で入力欄にフォーカス → 生成を停止
4. 入力欄にフォーカス → フォーカスを一覧（または本文）に戻す
5. 複数選択を解除（複数選択は未実装のため、いまは該当しない）
6. オーバーレイ表示中のパネルを閉じる
7. 上へ戻る：子の会話 → 親の会話、それ以外の会話とタイムライン → ホーム（会話から戻るとホームではその会話が選ばれている）

`Esc` は承認・拒否・エージェント Run の停止を決して行わない。

## 8. 状態ごとの見せ方

### 8.1 初回起動（オンボーディング）

ウィザードは 1 画面。最初のストリーミング応答まで 60 秒以内を目標にする。

```
┌──────────────────────────────────────────────────────────────┐
│                 AI エージェントのチームを始めましょう                │
│        LLM の接続先を選んでください。あとから設定で変更できます。     │
│                                                              │
│  ┌─────────────────────────┐   ┌─────────────────────────┐   │
│  │ ⇄ LiteLLM Proxy に接続   │   │ ▷ デモモードで試す        │   │
│  │ 社内やお手元の Proxy を  │   │ 組み込みの模擬モデルで、  │   │
│  │ 使います。               │   │ 費用をかけずに並列実行を  │   │
│  │                         │   │ 体験できます。            │   │
│  └─────────────────────────┘   └─────────────────────────┘   │
│                       ← → で選択 · Enter で決定                │
└──────────────────────────────────────────────────────────────┘
```

- **LiteLLM Proxy に接続**：URL と API キー（入力は伏せ字、値は Core Daemon の設定にだけ保存し UI は保持しない）→ `接続テスト`。成功で `12 個のモデルが使えます` と既定モデルの選択。失敗は原因別に 1 文（`接続できませんでした。URL とネットワークを確認してください` / `認証に失敗しました。API キーを確認してください`）。
- **デモモード**：即座に開始。タイトルバーに `デモ` バッジを常時表示し、コストは `$0.00（デモ）`。司令室に提案カード `デモ：2 人のエージェントで README を改善する` を出し、Enter 一発で Orchestrator → 2 Worker → 統合 → 承認までの一連（Vertical Slice）を体験できるようにする。
- 次の任意ステップ：`プロジェクトを追加`（Git リポジトリのフォルダを選ぶ）。`あとで` で飛ばせる。
- プロジェクトの追加は、入力中（350ms 後、貼り付けならすぐ。エクスプローラーの「パスのコピー」の引用符は外す）に `project.inspectRepo { path }` でフォルダを確かめ、作る前に結果を出す（結果は protocol の `RepoInspection` をそのまま読む）：`ok: false` なら欄の下にデーモンの理由（日本語）を出して `プロジェクトを追加` を無効に。リポジトリの中のフォルダなら `ルート … を使う` で 1 クリックで直せる。`ok` ならブランチ（`feature-x（既定は main）`）を示し、名前（`suggestedName`、プレースホルダー）・既定ブランチ（`defaultBranch`、作成時にも渡す）・テストコマンド（`suggestedTestCommand`、未入力のときだけ）を埋め、未コミットの変更があれば注意の帯（`Worker の worktree は最後のコミットから作られるため、未コミットの変更は Worker に見えません`）。同じリポジトリが既にプロジェクトなら（`existingProjectId`）追加を止め、`このプロジェクトを開く`。確かめられない（接続断・メソッドなし）ときは作成時に検証する。

### 8.2 空状態

空状態は「次の一手」を必ず 1 つ示す。イラストは使わない（アイコン 1 つ + 見出し + 1 文 + 操作）。

| 場所 | 見出し | 補足 / 操作 |
|---|---|---|
| 司令室（何も動いていない） | 何を進めますか？ | 入力欄をその場に置く。下に提案チップ 3 つ（`チャットで相談する` / `エージェントに作業を任せる` / `Orchestrator に分担させる`） |
| 要対応 0 件 | すべて順調です | あなたの出番はまだありません。（実行中が 0 件なら非表示） |
| 新しいチャット | — | 入力欄のプレースホルダー `何でも聞いてください` と、モデルチップのみ |
| タイムライン（フィルタで 0 件） | 条件に合うイベントはありません | `フィルタをクリア` |
| 変更タブ | まだ変更はありません | このRunがファイルを編集すると、ここに差分が表示されます。 |
| 検索 0 件 | 「◯◯」に一致するものはありません | `AI に頼む` を提示（パレットと同じ） |

### 8.3 読み込み

- 150ms 未満は何も出さない（ちらつき防止）。150ms〜はスケルトン。1 秒を超えたら何を待っているかを 1 行で添える（`デーモンの起動を待っています…`）。
- スケルトンは最終レイアウトと同じ行高・列幅の `bg-hover` の角丸矩形。シマー（光が流れる演出）は使わない。
- キャッシュがあれば古いデータを即表示し、裏で更新する（TanStack Query）。再取得でスケルトンに戻さない。
- 全画面スピナーは使わない。唯一の例外は初回のデーモン起動（アプリマークのみの静かな起動画面、最大 3 秒で状態文を表示）。

### 8.4 エラー

エラーは「何が起きたか」+「どうすればいいか」を 1〜2 文で、発生した場所に出す。モーダルはデータ損失の確認にだけ使う。

| コード | 見せ方 | 文言の例 |
|---|---|---|
| `invalid_params` | 入力欄の下にインライン（`--st-failed`、`text-meta`） | `URL の形式が正しくありません` |
| `forbidden` | 操作した場所にインライン、足りない権限を名指し | `この操作には「セッションの作成」権限が必要です` + `権限を付与` |
| `budget_exceeded` | Run 内に注意色の帯 | `予算の上限（$3.00）に達したため一時停止しました` + `予算を追加` / `ここで終了` |
| `conflict` | トースト | `この worktree は Worker · 認証機能の改善 が使用中です` |
| `limit_exceeded` | 情報トースト（エラー扱いしない） | `同時実行の上限（10）に達したため、待機列に追加しました` |
| `internal` | トースト（自動で消えない） | `予期しないエラーが発生しました` + `詳細をコピー` |

- **Run の失敗**は要対応カードで見せる：最後のエラーの先頭 2 行（mono）、`再試行` / `方針を変えて再試行`（追加指示の入力欄が開く）/ `ログを見る`。
- **デーモン切断**：メインの上端に 32px の帯 `Core Daemon に再接続しています…（3 秒後に再試行）`、補足 `エージェントはバックグラウンドで動き続けています`。操作ボタンは無効化し、ツールチップで理由を示す。再接続後は差分イベントを取り込み、帯は 120ms で消える。

### 8.5 トーストと通知

- 右下、幅 360px、余白 16px、最大 3 件積み重ね（間隔 8px）。4 件目以降は最古をまとめて `ほか 2 件`。
- 情報・成功は 4 秒で消える（ホバー中は停止）。エラーと判断を求めるものは消えない。
- 取り消せる操作は `元に戻す`（`Ctrl+Z`）付きで 5 秒。`Ctrl+Z` は表示中のいちばん新しい `元に戻す` を実行する。出現は y 8px + 不透明度 180ms、消失は不透明度 120ms。
- **見ている場所で起きたことはトーストにしない**（Focus 中のセッションが完了しても出さない）。
- **出番の通知**（`app/attention.ts`）：新しい出番（`attention.opened`：質問・確認・失敗・確認待ち・予算・止まっている）。ウィンドウが裏にあるときは OS 通知、前にあるときは見ていない出番だけをアプリ内トースト（`開く`）にする。ホームはすべての出番を上端に並べているので、ホームでは出さない。会話を開いているときは、その会話の出番だけ出さない。同種は 10 秒に 1 回まで、その間の分は窓の終わりに 1 件の要約（`質問が 3 件あります`）にする。2 分より古いイベント（再接続の再送）は通知しない。設定の `通知` で OS / アプリ内をそれぞれ切り替える。通知音は鳴らさない。
- OS 通知は `lib/notify.ts` の `notify()` だけが出す：デスクトップアプリでは tauri-plugin-notification のコマンド（`plugin:notification|is_permission_granted` / `request_permission` / `notify`。main ウィンドウの capability はこの 3 つだけを許す）を直接呼び、ブラウザでは Web Notification API を使う（プラグインの `window.Notification` 置き換えは Windows で最初「拒否」になるため使わない）。許可は求めない（設定のトグル / `許可する` ボタンを押したときだけ求める）。OS 通知のクリックで該当場所を開くのはブラウザだけ（プラグインはクリックを返さない）。

### 8.6 設定の Core Daemon 項目

- `エージェントの権限`（Core Daemon が強制）：既定のプロファイル（§5.5 のラジオ、変えた瞬間に保存）、`Claude Code の Auto mode`（オン / オフ）、`判定する場所`（サーバー / 手元の分類器、変えた瞬間に保存）と `分類器のモデル（LiteLLM 経由のとき）`（離れたときに保存）。プロファイルを知らない古いデーモンでは `この Core Daemon は権限のプロファイルに対応していません。`。
- `実行の制約`（Core Daemon が強制）：同時実行の上限、委譲の深さ、`LLM 呼び出しごとの予約額（USD）`（`llmCallReserveUsd`、0〜100、既定 0.25。チャット・Orchestrator の LLM 呼び出しの前に予算から確保して実費で精算する。確保できない呼び出しは断られるので、同じ予算を共有する並列の Run が上限を超えない。0 で予約しない）。数値欄は離れたときに保存し、範囲外は元の値に戻す。
- `Core Daemon`：`再起動のあと Orchestrator を再開`（`autoResumeOrchestrators`、既定オン。中断した Orchestrator を権限が有効なら自動で再開し、オフならチャットにお知らせだけを残す）、バージョン・データ・プロセス、停止ボタン。
- 停止は `system.shutdown`（人間だけ）。押すと `system.info` で実行中の Run を数えて確認する：0 件なら `force: false`、N 件なら `N 件を中断して停止` で `force: true`。確認のあとに Run が始まってデーモンが `conflict` を返したら、その件数でもう一度聞く。デスクトップアプリではシェルがすぐ新しいデーモンを起動するので、ボタンも文言も `再起動`（`Core Daemon を再起動しますか？`）にする。中断した Run・Task は再開でき、Orchestrator の扱いは上の設定に従う、と確認の本文で言う。

## 9. マイクロコピー

### 9.1 トーン

- 丁寧だが硬すぎない「です・ます」。主語は省く。1 文を短く。
- 名詞止めのラベル、動詞のボタン。ボタンは何が起きるかが分かる語にし、`OK` / `はい` を使わない。
- 擬人化しすぎない。エージェントは「エージェント」「Worker」と呼び、感情表現（`がんばっています！`）はしない。
- 感嘆符・絵文字は使わない。英語の固有名詞（Run、Task、worktree、Orchestrator）はそのまま、数字と単位は半角。

### 9.4 数値・時刻の表記

- 経過時間：`12:04`、1 時間以上は `1:02:33`。
- 時刻：今日は `14:03`、それ以前は相対（`3 分前` `昨日 14:03` `10/27`）。ツールチップに絶対時刻 `2026/10/29 14:03:21`。
- コスト：確定値 `$0.42`、推定値 `≈$0.42`（ツールチップ `トークン数からの推定値です`）、未計測 `—`（ツールチップ `コストを取得できない接続です`）。concept §5.1 の reported / estimated / unknown をそのまま表す。
- 件数：`3 件`、ファイル差分：`+58 −12`（`−` は U+2212）。
- 主体：`あなた` / AI はセッション名か役割名（`Orchestrator（設計チャット）`）/ `システム`。

## 10. 手触りの性能予算

見た目と同じくらい、ここを守ることが「手放せない」の条件になる。E2E とプロファイルで継続的に確認する。

| 項目 | 予算 |
|---|---|
| キー入力・クリックへの視覚的反応 | 16ms 以内（1 フレーム） |
| モード切替、一覧 → Focus | 100ms 以内に描画完了 |
| コマンドパレットの表示 | 50ms 以内 |
| 10 本同時ストリーミング | 60fps を維持（デルタも Control API のイベントも rAF 単位でまとめて反映する、非表示の行は更新しない、変化のない行は再描画しない）。`pnpm --filter @acc/desktop e2e:perf` で本番ビルドを測る（10 Run 同時開始・ストリーミング中・Focus のそれぞれで、フレーム間隔の p95 が 34ms 以下、200ms を超える長いタスクがないこと） |
| 経過時間の表示 | アプリ全体で 1 本の 1 秒タイマーを共有（行ごとの `setInterval` 禁止） |
| アクティビティ行の更新 | 1 行あたり最大 4 回/秒 |
| 長い会話（1,000 メッセージ）・タイムライン（10 万イベント） | 仮想化して初期描画 200ms 以内、スクロールでフレーム落ちしない |

## 11. 実装メモ（共通部品）

- `StatusIcon`、`StatusLabel`：§2.4・§2.5・§9.2 を唯一の定義にし、ラベルや色を各所で書かない。
- `Kbd`：ショートカット表記。OS で `Ctrl` / `⌘` を切り替える。ショートカット定義は 1 か所（`shortcuts.ts`）に集め、ボタン・パレット・一覧表示はそこから引く。
- `useStickToBottom`：§6.1 の自動スクロール。チャットとタイムラインで共有。
- `useDeferredReorder`：§3.2 の並べ替え保留。
- `ElapsedTime`、`Cost`：共有タイマーと `reported / estimated / unknown` の表記を内包。
- アクセシビリティ：要対応件数の変化は `aria-live="polite"` で読み上げる（`承認待ちが 1 件増えました`）。状態は色・形・文字の 3 つで伝える。Radix のフォーカス管理を崩さない。
