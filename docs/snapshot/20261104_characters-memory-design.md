# 2026-11-04 設計メモ：キャラに「残り続ける自分」を持たせる

AI 同士の会話（`architecture.md` §2.21）を本物のモデルで試した続き。今のキャラはその場の会話の中にしかいない。キャラにプロフィールと記憶を持たせ、雑談・仕事・会議のどこに呼んでも同じ「その子」にしたい。まだ決定ではなく、作り始める前の考えをまとめたもの。

## なぜ

- 今のキャラは `session.spawn` の `persona` で、その会話が終わると消える。試したら会話の中で設定が育った（ハクの「リスに梅おにぎりを奪われた過去」、ソネの「倒壊した 20cm パンケーキ」）のに、次には持ち越せない。
- 構想の「10 人の AI エージェントを率いる」：率いる相手に顔と過去があると、並べた会話ではなく「メンバー」になる。
- D-Mascot（デスクトップ常駐のマスコット。別のリポジトリ）は記憶の仕組みを持つのに「うまく動いている感」が薄い。記憶がほぼ全部「あなたについて」で、まる自身の過去は残らない（自分の発言は事実から外している）。だからキャラが積み上がらない。思い出し方は「全部入れる」。

## 目指す体験

- 「ハク」と雑談する、ハクに仕事を振る、ハク・ルナ・ソネで会議する。どれも同じハクで、前の続きを覚えている。
- 会話で生まれた設定と関係が、次の会話でも生きている。
- それでも、仕事の邪魔はしないし、昔の話を蒸し返さない。
- 何を覚えているかが見えて、消せて、直せる。

## 概念：増やすのは「キャラ」だけ

- **キャラ** = 名前・プロフィール（今の persona）・既定のモデル・記憶。会話ではなく、会話に「出る」もの。
- 会話は今のまま。キャラが出る会話は `characterId` を持ち、プロフィールは写しではなく参照する（直せば次の発言から効く）。
- 入口は今の場所に足すだけ：右腕に「ハクと話したい」「ハクに頼んで」、指揮役の `session.spawn` に `characterId`、新しい会話でキャラを選ぶ。
- その場で立てるキャラ（今の `persona`）は残す。気に入ったら「残す」でキャラになる。

## 記憶は 3 種類

| 種類 | 例 | 材料 | 上限の目安 |
|---|---|---|---|
| **自分** | リスに梅おにぎりを奪われた／ツナマヨは邪道だと思っている | そのキャラ自身の発言 | 20 件 |
| **関係** | ルナのズボラにはツッコむ／ソネとは鮭の皮で意気投合した | 相手との会話（相手ごと） | 相手ごと 5 件 |
| **あなた** | 朝が弱い／費用にうるさい | 人の発言だけ（AI の発言は使わない） | 15 件 |

- **自分**は D-Mascot と逆で、AI 自身の発言が一番の材料になる（とっさに作った設定が、次から本当の過去になる）。1 回で定着してよい。
- **あなた**は D-Mascot の作りをほぼそのまま使う。1 回きりのことは定着させない（くり返し出たら事実）。
- **誰が何を知っているか**：あなたの記憶は、そのキャラが直接聞いたことだけ（又聞きはしない）。全員が同じことを知っているのは不自然で、ちょっと怖い。
- 生の会話は今までどおり会話に残る。記憶はそこから要約したもの。

## 書き方

- **会話の区切りに 1 回だけ**整理する（そのキャラの会話がしばらく動かない／木が終わった）。安いモデルに「今の記憶 + この会話」を渡し、上限つきの新しい一覧を丸ごと受け取って置き換える（D-Mascot の毎日の整理と同じ形。忘れるのも機能のうち）。
- 迷ったら変えない（間違った記憶の操作は、間違った記憶より悪い）。
- 人が「違うよ」と言ったら直す。**人が消したものや直したものは、あとの整理で戻さない**（D-Mascot では、訂正と毎日の整理がぶつかって訂正が消える問題が残っている）。
- 何を覚えたかは見える（キャラのページで、何がいつ増えて何が消えたか）。

## 思い出し方

- 記憶はキャラの前提（system）側に置く。量が小さいうちは選ばずに全部入れる（D-Mascot の判断と同じ。ベクトル検索は要るまで入れない）。上限で量を抑える。
- **場面で強さを変える**：雑談は 3 種類すべて／会議は自分と同席者との関係／仕事を振るときはプロフィールとあなたの好みだけ。
- 「3 日前」のような日付の言い方はコードで計算して渡す（LLM に計算させると間違える。D-Mascot で実際に起きた）。
- 長く出てこない出来事は、整理のときに落とす候補にする。

## 費用

- **1 メッセージあたりの追加呼び出しは 0**。整理は会話の区切りに 1 回、安いモデルで行う（D-Mascot は 1 メッセージごとに 2 回呼んでいる）。
- 記憶は system 側に置き、会話の途中では書き換えない。キャッシュの接頭辞を壊さない。D-Mascot は記憶を毎回変わる user 側に入れていて、キャッシュが効かない。
- 整理の費用も、そのキャラの費用として見せる。予算と日次上限はデーモンが強制する。

## 画面（ざっくり）

- キャラの顔：頭文字の丸と色（今の `SpeakerMark`）。どこに出ても同じ顔にする。
- キャラの一覧：サイドバーかホームに、顔と名前だけ並べる。
- キャラのページ：プロフィール、覚えたこと（3 種類。消す・直す）、出た会話、費用。
- 会話の見出しとチップに、キャラの顔を出す。

## 段階

1. **キャラを残して呼べる**（記憶なし）：キャラのデータと `character.*` の API、`session.create` / `session.spawn` の `characterId`、一覧とページ、右腕から呼べる。
2. **自分と関係を覚える**：区切りでの整理、前提への差し込み、覚えたことの表示と消去。
3. **あなたを覚える**：直接聞いたことだけ、人の訂正を最優先。
4. （当面やらない候補）キャラから自分で話しかける。D-Mascot の自発発言のようなもの。

## 決めていないこと

- キャラはプロジェクトをまたぐか（全体で 1 つの名簿が自然そう）。
- 右腕もキャラにするか（右腕にプロフィールと記憶があると、相棒らしさが出る）。
- エージェント（Claude Code）として仕事をするときに、キャラをどこまで効かせるか（報告の口調だけ、など）。
- 同じキャラが同時に複数の会話に出たとき、整理を順番に並べる方法。
- キャラを消したとき、その記憶と出た会話をどう扱うか。
