## 決めたこと（仕様に書いていなかったもの）

- **整理のモデルの既定は、名簿で入力単価が一番安いモデル**（なければオフラインの `mock/memory`）。設定の画面ではまだ選べない（`settings.update` の `members.memoryModel` では選べる）。
- **名簿から外しても記憶は消さない**。外すのは 5 秒の元に戻すがある操作なので、戻したら記憶もある方が自然。仕様の「消したら記憶も消す」は、完全に消す操作を作るときに入れる。
- 会議で読む関係は「同じ指揮役の下で話している、名簿のメンバー」とのものだけ（その場のキャラは名簿にいないので関係を持たない）。
- 関係の記憶は、整理のモデルには相手の名前で書かせ、デーモンが id に戻す（知らない名前は捨てる）。

## 確かめていないこと

- **本物のモデルで整理していない**。見るべき点：(a) 1 回の会話で自分の設定が拾われるか、(b) 「あなた」に 1 回きりのことを書かないか、(c) 仕事の中身（社名・数字）を書かないか、(d) 返事が JSON で返るか（返らなければ 1 時間あけて再試行）、(e) 1 回の費用。
- 口調の守り具合はモデル次第で、それも味という方針（Luna・Haiku は崩れやすく、Sonnet・Opus・Terra・Sol はよく守る、という見立て）。崩れても枠や再試行で縛らない。成果物に口調が漏れるのは不具合として扱う。
