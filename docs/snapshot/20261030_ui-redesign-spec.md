# 2026-10-30 画面の作り直し：仕様（UI トラックが従う契約）

土台（`20261029_redesign-spec.md`、会話の木・出番・費用・定期実行・`home.get`）の上に、デスクトップの画面を作り直す。合格基準はユーザーの言葉どおり：

> 10 人のエージェントが同時に動いている状態で、アプリを 5 秒間眺める。チャットもログも開かずに、全体の進捗・問題・人間の出番が分かるか？

## 0. 原則（判断に迷ったらここに戻る）

1. **文字で説明しない。** 配置・項目名・アイコン・色で意味を持たせる。段落の説明・文章の要約（「残り 3 件は順調…」）は禁止。補足は本当に必要な箇所だけ、ツールチップ（必要なときに出る）に置く。
2. **汎用。** コードは成果物の 1 種類にすぎない。ブランチ・diff・テストは、コードの作業のときだけ出す。
3. **概念を増やさない。** ユーザーに見せる語は 会話 / エージェント / 成果物 / 出番 と、操作の動詞（任せる・止める・再開・繰り返す・採用・反映）だけ。Task / Run / Grant / Worker / Orchestrator / Integration / ID / JSON は出さない。
4. **開かずに分かる。** 10 並列でも、チャットを開かずに「何をしているか・どこで詰まっているか・自分の出番か」が分かる。
5. **情報の意味と動きの意味を一致させる。** 出番が来たら並びが自然に変わる（派手なポップアップは出さない）。カーソルの下で物を飛ばさない（並べ替えはホバー・キーボード操作中は保留）。
6. 文言は日本語の名詞句か動詞 1〜3 語。句点のある文は、エラーと空のときの 1 行だけ。

## 1. 視覚の語彙（全画面で共通。`src/lib/states.ts` と `src/components/ui/` に 1 か所だけ定義する）

### 1.1 会話の状態（`SessionState`）

色だけでなく形でも区別する（色覚に頼らない）。

| state | 色トークン | アイコン（lucide） | ラベル（ツールチップ・読み上げ） |
|---|---|---|---|
| needs_you | amber（warning） | `Hand` | あなたの出番 |
| failed | red（danger） | `TriangleAlert` | 失敗 |
| working | blue（accent） | 回る輪（`LoaderCircle` を回転。動きを減らす設定では静止した `Circle` を太線で） | 作業中 |
| supervising | violet | `Diamond`（子が動いている間はゆっくり明滅） | 子の作業待ち |
| queued | gray | `CircleDashed` | 順番待ち |
| review | violet | `Eye` | 確認待ち |
| stopped | gray | `CirclePause` | 停止中 |
| done | green | `CircleCheck` | 完了 |
| idle | gray（薄） | `Circle` | 待機 |

優先順（並べ替え・集計の順）：needs_you > failed > working > supervising > queued > review > stopped > done > idle。

### 1.2 そのほかのアイコン

- 役割：chat → `MessageSquare`、agent → `Bot`、supervisor → `Diamond`（塗り）。始めた者：schedule → `Clock`（小さく右上に重ねる）、ai → なし（木の位置で分かる）。
- 出番の種類：question → `MessageCircleQuestion`、approval → `ShieldQuestion`、failure → `TriangleAlert`、review → `Eye`、budget → `Coins`、stuck → `Repeat`。
- 成果物：document → `FileText`、data → `Table`、link → `Link`、files → `Files`、code → `GitCompare`。
- 作業場所：なし → 表示しない、folder → `Folder`、worktree → `GitBranch`。

### 1.3 数字

- 費用：`$0.21`（小数 2 桁）、0.005 未満は `<$0.01`、0 は出さない（`—` も出さない）。推定値かどうかはツールチップにだけ出す（`≈` は表示しない）。
- 経過時間（`stateSince` から）：作業中・待ちは `30秒` `4分` `2時間`、終わったものは `12分前` `昨日`。1 秒ごとの更新は作業中の項目だけにする（`useNow`）。
- 予算：細いメーター（使用 / 上限）。80% を超えたら amber、上限で red。

### 1.4 共通部品（U0 が作る。各トラックはこれを使い、勝手に作り直さない）

| 部品 | 中身 |
|---|---|
| `StateIcon({ state, size })` | 1.1 の色・形。aria-label 付き |
| `SessionChip({ card, size: 'md' \| 'sm', selected, onOpen })` | ホームのチップと会話の子の列に使う。1 行目：状態アイコン＋題（省略は末尾）。2 行目：作業中は `now`、出番があれば出番の題（amber）、失敗は失敗の題、完了は成果物のアイコンと数、確認待ちは成果物の種類＋（コードなら +N）。3 行目（md のみ）：経過時間と費用を左右に。needs_you / failed は枠線の色。選択中はフォーカスリング |
| `AttentionRow({ attention, sessionTitle, compact, onRespond })` | 出番 1 件を 1 行で：種類アイコン・会話の題（チップ風、押すと会話へ）・題・選択肢ボタン（`tone` で色、キー表示 1〜4。approval は Y / N）・`allowText` なら返信欄（Enter で開く）・詳細の開閉（`detail` があるときだけ ▸）。応答中はボタンを無効にせず楽観的に消す（失敗したら戻してトースト） |
| `CostMeter({ usedUsd, limitUsd })` | 1.3 の予算メーター＋金額 |
| `Elapsed({ since, settled })` | 1.3 の経過時間 |
| `OutputIcon({ kind })` / `RoleIcon({ role })` | 1.2 |

│ ── 会話の木 ──    │                                      │          │
│ ◆ ローンチ準備 ●●●│                                      │          │
│   ├ ✋ FAQ 担当    │                                      │          │

- **画面は 3 つ**：ホーム（旧 司令室。アプリの顔、起動時はここ）、会話（旧 フォーカス）、タイムライン。`useUi.mode` は `'home' | 'session' | 'timeline'`。旧 `'command' | 'focus'` は永続化の移行で読み替える。
- **タイトルバー**：サイドバー開閉、戻る・進む、検索（パレット）、今日の費用メーター（押すと費用のポップオーバー：今日の木ごとの棒と日次上限の変更。U5）、出番の数（✋＋数。0 なら出さない。押すとホームの出番の先頭へ）、接続の点。プロジェクトの切り替えはタイトルバーから外す（サイドバーでまとめる）。
- **サイドバー**（U2）：上から「＋ 新しい会話」「ホーム（出番の数）」「タイムライン」、会話の木、下に「設定」と接続。旧「要対応・実行中・最近」の節は消す（ホームと重複）。
- **成果物パネル**（U4）：会話を開いていて、その会話（または子孫）に成果物があるときだけ右に出る。旧 DetailPanel（概要 / 変更 / テスト / ログ のタブ）は消す。
- **キーボード**（`GlobalShortcuts`）：Ctrl+K 検索、Ctrl+N 新しい会話、Ctrl+1 ホーム、Ctrl+2 タイムライン、Alt+← / → 戻る・進む、Esc は「開いている物を閉じる → 親の会話 → ホーム」の順に戻る。ホーム内は §3.4。

## 3. ホーム（U1）

`home.get` 1 回＋イベントで描く（`applyHomeEvent` で差分を当て、`refetch` のときだけ取り直す。取り直しは 300ms でまとめる）。

### 3.1 並び

1. **出番の列**（上端）：`snapshot.attention` を priority 順に `AttentionRow` で縦に並べる。0 件なら列ごと出さない（「出番はありません」も出さない）。6 件を超えたら 5 件＋「あと N 件」（押すと全部）。新しい出番は上からすっと入る（layout アニメーション 180ms）。
2. **木のレーン**：`snapshot.trees` の順（daemon の並び）。1 本のレーンは：
   - **見出し 1 行**：役割アイコン、題（押すと根の会話を開く）、状態の帯（`counts` を 1.1 の色で比例配分した 6px の帯。幅 120px。ホバーで内訳のツールチップ）、次回の予定（`Clock` ＋ `9:00`。`nextRunAt` があるときだけ）、木の費用（`spend.treeUsd`、上限があれば `CostMeter`）。
   - **子のチップ**：`nodes` を `SessionChip md` のグリッド（`minmax(168px, 1fr)`）。並びは 1.1 の優先順、同じ状態の中は daemon の順。並べ替えは `useDeferredReorder` でホバー・キー操作中は保留。孫（depth 2 以上）は今は出ない前提（深さ 1）。`hiddenNodes` > 0 なら末尾に「+N」チップ（押すと根の会話）。
   - **子のいない木**（普通の会話・定期実行の根）：チップを出さず、見出しの行だけ（右端に根の状態アイコン、作業中なら `now`）。
3. **落ち着いた木**（出番なし・作業中なし・待ちなし。つまり done / idle / stopped だけ）は、見出しだけの 1 行に縮める。並びは daemon のまま。
4. **空のとき**（木が 0 本）：画面中央に入力欄 1 つ（プレースホルダ「何を頼みますか」）と、その下に作業場所の選択（なし / フォルダ / コード のアイコン切り替え）。説明文・3 択カードは出さない。

### 3.2 ホームの入力欄

木が 1 本以上あるときも、ホームの下端に 1 行の入力欄を置く（「何を頼みますか」、Enter で新しい会話を作って送り、その会話を開かずにホームに留まる。Ctrl+Enter で作って開く）。ここで「任せる」アイコンを押してから送ると、その会話は最初から任せた状態になる（`session.create` → `session.delegate` → `session.send`）。

### 3.3 動き

- 状態が変わったチップは色が 200ms で移る。needs_you になったチップは枠が amber に変わり、1 回だけ柔らかく明滅する（動きを減らす設定では明滅しない）。
- レーンの順が変わるとき、チップと同じく保留してから layout アニメーション。

### 3.4 キーボード

- J / K（または ↓ / ↑）：出番の行 → 各レーンのチップ、の順に選択を動かす。
- Enter：選んだものを開く（出番なら返信欄、チップなら会話）。1〜4：選んだ出番の選択肢。Y / N：approval の許可 / 拒否。
- 選択は画面外に出たらスクロールで追う。

## 4. サイドバー（U2）

- 会話の木：`session.list({ rootsOnly: true })`（または `home.get` の木と同じ並び）。1 行は：状態アイコン、題、右端に（子がいれば）子の状態の小さな点の列（最大 6 個、あとは +N）、または作業中なら経過時間、定期実行の根なら `Clock`＋次回時刻。
- 子は既定で折りたたみ。▸ で開くと字下げ＋ツリー線で子の行（`session.tree`）。いま開いている会話の祖先は自動で開く。
- プロジェクトが 2 つ以上あるときだけ、プロジェクト名の小見出しでまとめる（プロジェクトなしの会話は先頭）。プロジェクトの追加・編集は小見出しのメニュー。
- 古い会話（落ち着いてから 7 日以上）は「以前」に折りたたむ。アーカイブは行のメニュー。
- 幅は既存の `sidebarWidth`（ドラッグで変更）。

## 5. 会話（U3）

### 5.1 見出し

- 1 行目：（子なら）親の会話へのチップ「↑ 親の題」、題（ダブルクリックで編集）、状態アイコン、右側に費用（自分 / 木）と予算メーター、操作ボタン（アイコンのみ、ツールチップ付き）：任せる（`Diamond`、U5 の `DelegateButton`）、繰り返す（`Clock`、U5 の `RepeatButton`）、止める / 再開（木ごと）、…メニュー（アーカイブ・費用の内訳）。
- 2 行目（子がいるときだけ）：子のチップの列（`SessionChip sm`、横スクロール）。押すとその子へ移動。

### 5.2 本文

- 子の最初のメッセージ（`meta.brief`）は**依頼カード**：目的（1〜2 行）、完了条件（`doneWhen` のチェックリスト。成果物があれば ✓）、作業場所のアイコンとパス末尾、予算メーター。依頼の生テキスト・`acc-mock` のブロックは出さない。
- 指揮役の起床（`meta.wake`）は**状況カード**：1 行で「子の状態アイコンの列＋変わったもの」。開くと詳細。
- ツールの呼び出しは既存どおり折りたたみ（1 行の名詞句。`now` と同じ言い方）。
- 途中から開いても、生成中の本文がすぐ見える（`session.messages` の `streaming` を使う。監査で見つかった不具合 1）。
- 送信待ちのメッセージ（`delivery: queued`）は時計の印。実行に入ったら（`injected` / `started`）印が消える。
- この会話の出番は、入力欄のすぐ上に `AttentionRow` で固定表示する。

### 5.3 入力欄

- 実行中に送ると、chat / supervisor は「次の区切りで渡す」（何も選ばずにそのまま送れる）。agent は既定で順番待ち、入力欄の左の `Zap` の切り替えで「割り込む」（`interrupt: true`）。
- **Ctrl+N は会話をすぐ作らない**（不具合 8）。下書きの画面になり、最初の送信で `session.create`。下書きの画面には、プロジェクトのチップと作業場所の切り替え（なし / フォルダ / コード）だけを置く。
- モデルの選択は既存のピッカーを入力欄の右下に残す。

### 5.4 消すもの

チャットの「変更 / テスト / ログ」タブ、Run 履歴と attempt 番号、「Worker:」接頭辞、生の JSON、承認文言の二重（「〜を承認しますかを承認しますか」、不具合 3）。

## 6. 成果物（U4）

- 右のパネル（幅はドラッグ可、既存の `panelWidth`）。上に成果物の一覧（アイコン＋題＋どの子が作ったか）、選ぶと下に表示。
- document：Markdown を描画。data：表（CSV / JSON 配列。先頭 500 行）。files：一覧（押すと OS で開く）。link：題と URL、押すと開く。code：diff（既存の `DiffViewer`）と「採用」「やり直す」。採用は `artifact.review` → 反映（`integration` は内部。UI の語は「反映」）。
- 完了条件（`brief.doneWhen`）があれば一覧の上にチェックリスト。
- 旧 `IntegrationView` の全画面レビューは、コードの成果物を大きく見るとき（パネルの「広げる」）にだけ使う。

## 7. 任せる・繰り返す・費用・設定・初回（U5）

- **任せる**（`DelegateButton`）：押すだけで既定値で `session.delegate`（説明のダイアログは出さない）。任せている間はボタンが塗りの `Diamond` になり、押すと小さなポップオーバー：予算（金額の入力）、同時に動かす数、作業場所（なし / フォルダ / コード の許可）、「任せるのをやめる」。
- **繰り返す**（`RepeatButton`）：ポップオーバーにプリセット（毎朝 9:00 / 平日 9:00 / 毎週月曜 9:00 / 毎時 / 自分で書く（cron））、`schedule.preview` で次の 3 回、1 回あたりの予算。作ったら見出しに `Clock 9:00`。
- **費用のポップオーバー**（タイトルバー）：今日の合計と日次上限（その場で変更）、木ごとの横棒（上位 8 本）、モデル別の小計。`cost.summary` を使う。
- **設定**：最初に見えるのは 3 つだけ：接続（LiteLLM の状態と「変更」）、任せ方（おまかせ / 標準 / 慎重 の 3 つのセグメント。各アイコン＋語、説明文なし、ツールチップに 1 行）、1 日の上限（$）。外観（テーマ・動き）を 1 行。ほかはすべて「詳細」の折りたたみ（自動判定、判定モデル、同時実行数、通知、ショートカット、診断）。各項目の下の説明段落は消す。
- **初回**：1 画面。接続先（LiteLLM の URL とキー、「確かめる」）と「あとで（モックで試す）」。モックで試すと、デモの会話が 1 つでき、任せた状態で 3 人の子が動き出す（新しい API：`session.spawn`）。

## 8. タイムライン（U6）

- 既定は**人の出来事だけ**：依頼・質問・失敗・完了（成果物つき）・採用・定期実行の発火。木（根の会話）ごとにまとまり、各行は 時刻・アイコン・会話のチップ・名詞句。
- 「詳細」の切り替えで、ツールの結果・予算・受信箱・起床も出す。
- 行を押すと、その会話のそのメッセージへ移動して一瞬光る（既存の `jumpTo`）。
- 1 回の実行が分かれて見える不具合（不具合 9）は、実行単位でまとめて直す。

## 10. 監査の場面（U0。全トラックが自分の画面の確認に使う）

`scripts/audit-scene.ts` を新しい API で作り直す（mock のモデルと mock ランタイムだけ。本物の API は呼ばない）。1 つの場面で次を同時に作る：

- **任せた会話 A「新製品ローンチ準備」**（プロジェクトなし）：子 5 人（作業場所なし）＝ 作業中 2（長い sleep、`now` が出る）、質問で出番 1（`human.ask`、選択肢つき）、失敗 1、完了 1（文書の成果物）。予算は 8 割ほど使った状態。
- **任せた会話 B「ログイン改善」**（git のプロジェクト）：子 3 人（worktree）＝ 確認待ち 2（コードの成果物）、作業中 1（承認待ちの出番：コマンドの確認）。
- **任せた会話 C「市場レポート」**（フォルダのプロジェクト）：子 2 人（フォルダ）＝ 作業中 1、順番待ち 1（`after`）。
- **定期実行「朝のまとめ」**（毎朝 9:00、発火済み 1 回で完了、次回あり）。
- **普通の会話**：完了 2（「お詫びメールの下書き」「Excel の重複を消したい」）、生成中 1（長いストリーム）。
- 日次上限 $20、今日の合計が数ドルになるように費用を記録。

これで 10 人以上のエージェントが同時に「動いている」状態になる。`e2e/audit-shots.js` は少なくとも次を撮る：ホーム（1440×900 と 1280×800 の 2 サイズ）、ホームで出番を選んだ状態、サイドバーの木を開いた状態、会話 A（指揮役）、子（作業中・質問・失敗・完了）、会話 B の子（コードの確認待ち＋成果物パネル）、設定、費用のポップオーバー、繰り返すのポップオーバー、タイムライン（既定・詳細）、空のホーム、初回画面、ライトテーマのホーム。

各トラックは自分の画面のスクリーンショットを**自分の目で見て**、§0 の原則（とくに 1 と 4）に照らして直してから終える。テストが通るだけでは終わりにしない。

## 11. 品質の基準（全トラック共通）

- `pnpm check`（lint・typecheck・test）が緑。変更したコンポーネントには振る舞いのテスト（Testing Library）を付ける。
- 新しい useEffect は、外部との同期（購読・DOM）だけ。理由をコメントに書く。派生値はレンダー中に計算する。
- 1440×900 で、ホームに 3 本の木と 10 人の子がスクロールなしで収まる。
- ライト / ダークの両方で読める（トークンだけを使う）。
- 動きを減らす設定で、回転・明滅が止まる。
- 本物の API・LLM は呼ばない。ユーザーの `~/.acc` は使わない（`ACC_HOME` は一時フォルダ）。
