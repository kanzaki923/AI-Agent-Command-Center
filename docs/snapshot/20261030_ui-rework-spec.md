# 2026-10-30 画面の手直し：仕様（キラキラを戻す）

`20261030_ux-review.md` の手がかりを実装に落とす。土台（会話の木・出番・費用・定期実行）と画面の骨組み（`20261030_ui-redesign-spec.md`）はそのまま。変えるのは **何を主役にするか** と **見た目の署名**。

合格基準は 2 つ。

> 1. 10 人動いている状態を 5 秒眺めて、進捗・問題・出番が分かる（前回と同じ）。
> 2. 一言頼んだあとの 10 秒で、「チームが動き出した」と感じる。チップが生まれ、計画が見え、できたものが届く。

## 0. 原則（前回の §0 に足す）

7. **AI の声は消さない。** UI の説明文・要約文は出さない（前回 §0.1）。ただし監督役の判断の言葉（なぜこう分けたか、何を待つか）は製品の中身であり、カードとして見せる。
8. **数字は節目にだけ。** 費用・経過秒を常時並べない。見せるのは、予算の半分を超えた・長く動きすぎた・上限に当たった、の節目だけ。それ以外はツールチップ。
9. **面で区切る、線で区切らない。** 領域の境界は背景の段差。左の縦線（`border-l`）は使わない。カードは枠線より面の明度差。
10. **動きは 3 つの場面に集中する。** 生まれる（任せた瞬間）・届く（完了と成果物）・呼ばれる（出番）。この 3 つは必ず見える。ほかは静か。

## 1. 見た目の土台（`styles/index.css`・`tauri.conf.json`・`src-tauri`）

### 1.1 角

| トークン | 旧 | 新 | 用途 |
|---|---|---|---|
| `--radius-xs` | 4 | **2** | バッジ・Kbd・チップ状のラベル |
| `--radius-sm` | 6 | **3** | ボタン・入力・選択行・サイドバーの行 |
| `--radius-md` | 8 | **4** | カード・チップ・ツール行・出番の行 |
| `--radius-lg` | 12 | **6** | ポップオーバー・メニュー・ダイアログ・パレット |

`rounded-full` は点・メーター・アバターだけ。メインの左上の 10px の丸みはやめる。

### 1.2 面と線

- `--bg-surface` を地から一段はっきり上げる（dark `#16171B` → `#1A1B20`、`--bg-raised` → `#22232A`）。チップ・カードは `border-line-subtle` を外し面だけで区切る（`bg-surface`、枠なし）。枠線を残すのは、入力欄・出番の行（色の枠）・出番 / 失敗のチップ（色の枠）・ポップオーバー（`raised` の縁）だけ。
- **左の縦線は全廃**：メインと成果物パネルの `border-l` は外し、成果物パネルの地を `bg-app` にして段差で分ける。サイドバーの木の罫線（`TreeLines`）はやめ、字下げだけにする。思考過程の引用は `bg-surface` の面にする。
- 上の `border-t`（タイトルバーとの境）も外す。タイトルバーと地の段差で足りる。

### 1.3 透け（Tauri）

- 窓を `transparent: true` にし、Rust 側で `window-vibrancy`：Windows 11 は `apply_acrylic`（色 `(11, 12, 14, 170)`）、失敗したら `apply_mica`、それも失敗したら不透明のまま。macOS は `apply_vibrancy(Sidebar)`。適用できたかを `get_glass` コマンドで返す。
- UI は `get_glass` が真で、設定「透け」がオンのときだけ `<html data-glass="on">`。そのとき `--bg-app` を `rgb(11 12 14 / 0.62)`、`--bg-canvas` を `rgb(16 17 20 / 0.90)` にする（ライトは `rgb(243 243 245 / 0.70)` / `rgb(250 250 251 / 0.92)`）。面（surface / raised）は不透明のまま。つまり透けるのはサイドバー・タイトルバー・成果物パネルの地と、メインの地のごくわずか。
- Vite だけで開いたとき（Tauri なし）は何も透けない。撮影（Playwright）にも写らないので、透けは実機で目で確かめる。
- 設定の「外観」に `透け` のオン / オフを足す（Tauri のときだけ出す。既定オン）。

### 1.4 字

- チップの題を 14px / 500 に（`text-chat` の太さ違い）。ほかのトークンは変えない。
- 面の上の補足（`now`、成果物）は `text-meta` のまま。

## 2. チップ（`components/ui/SessionChip.tsx`）

```
┌ ◉ 競合 3 社の調査            ┐  ← 1 行目：状態アイコン＋題（14/500）
│   競合のストア情報を確認中      │  ← 2 行目：いまの作業 / 出番の題 / 失敗の理由 / 成果物
└──────────────────────────────┘     高さ 56px、面だけ（枠なし）
```

- **3 行目（経過秒と費用）をなくす。** 費用はチップに出さない。経過時間は、作業中で状態が 10 分以上続いているときだけ、2 行目の右端に `12分`（`text-fg-3`）。終わったものは出さない。
- ツールチップ（題にホバー）：`作業中 · 4分 · $0.21`。数字はここに退避する。
- 2 行目の既定：working → `now`（なければ `作業中`）、queued → `順番待ち`、needs_you → 出番の題（amber）、failed → 失敗の理由（red）、done / review → 成果物のアイコン＋題（1 件なら題、複数ならアイコンと数）、stopped → `停止中`。
- **面が呼吸する**：working のチップは面に状態色 4%〜9% の薄い色が 3 秒周期で行き来する（`acc-breathe-face`、疑似要素の opacity だけ）。動きを減らす設定では 6% で静止。supervising は使わない（チップは子だけ）。
- **生まれる**：レーンに新しく入ったチップは `opacity 0 → 1`・`y 6 → 0`・`scale 0.98 → 1` を 220ms、同じフレームで複数生まれたら 1 枚ずつ 60ms ずらす。レーン自体が新しいときは見出しが先、チップはそのあと。
- **届く**：done / review になった瞬間、面に `--st-done`（review は `--st-review`）12% が乗って 900ms で消える（`acc-arrive-once`）。needs_you の `acc-alarm-once` は残す。
- sm（会話の見出しの子の列）は 1 行目と 2 行目のまま、同じ規則。

## 3. ホーム（`components/home/`）

### 3.1 レーン見出し

```
◆ 新製品ローンチ準備                 2 / 5  ▬▬▬▬▬▬▬▬  📄 1          ← 1 行目
  来月 20 日に新製品「Komorebi ノート」を出す。発売までの準備を進めて   ← 2 行目：頼んだ一言（子のいる木だけ）
```

- 右端の列：**進み具合 `2 / 5`**（done ＋ review ／ 子の数、`tabular`）、状態の帯（従来）、**できたものの印**（成果物の種類アイコンと数。0 なら空）、次回（定期実行だけ）。
- **費用は、予算があって半分を超えたときだけ** `CostMeter` を出す（amber / red の節目を含む）。それ以外は帯のツールチップに `費用 $2.77 / $3.40`（上限なしなら `費用 $0.35`）。落ち着いた木も同じ。
- 2 行目は `HomeTree.goal`（根の最初の人のメッセージ、機械向けブロックを除いて 1 行に。daemon が返す）。題と同じ文なら出さない。子のいない木・落ち着いた木は出さない。
- 子が動いている間、役割アイコンの菱形は `acc-breathe`（既存）。止まっていれば静止。
- チップのグリッドは `minmax(184px, 1fr)`。

### 3.2 できたもの（新）

出番の列の下、レーンの上に **横一列**（高さ 64px、横スクロール、`aria-label="できたもの"`）。

```
┌ 📄 プレスリリース（案）  ┐ ┌ ⑂ 変更 +1 −0   ┐ ┌ ▦ 競合 3 社の価格 ┐
│ 新製品ローンチ準備 · 12分前│ │ エラーメッセージを直す│ │ 市場レポート · 1時間前│
└────────────────────────┘ └──────────────────┘ └────────────────────┘
```

- 中身：done / review の子（と子のない根）の成果物を新しい順に、最大 8 枚。`review` の成果物は枠が `--st-review`（判断が要る）。
- 押すとその会話を開く（成果物パネルが右に出る）。未読（`useUnread` の会話）なら題を明るく。
- 0 件なら列ごと出さない。
- 1 枚が増えるときは右端から `x 8 → 0` で 180ms。

### 3.3 入力欄

- 位置は下端のまま。高さ 44px、面 `bg-surface`、枠なし、フォーカスで `--focus-ring` の枠。プレースホルダは `何を頼みますか`。
- ◇（任せる）のトグルは残すが、ホームに木が 1 本もないとき（空のホーム）は **既定でオン**。
- 作業場所の 3 択はプロジェクトが 1 つ以上あるときだけ出す。

### 3.4 空のホーム（最初の 1 分）

```
                    ◆  何を頼みますか                      [任せる ◇]
                    来月のローンチ準備を進めて           ← 例（4 秒ごとに入れ替わる、薄い字）

                          ▷ 試してみる（3 人が動きます）
```

- 入力欄は中央、幅 560px、高さ 48px。その下に例の 1 行（`text-fg-4`、3 つを 4 秒ごとに切り替え、クロスフェード 180ms。動きを減らす設定では 1 つ目で固定）：`来月のローンチ準備を進めて` / `ログイン画面のエラー文言とテストを直して` / `毎朝 9 時に昨日のまとめを作って`。説明文ではなく例。
- `試してみる` は ghost ボタン 1 つ。既存の `startDemo`（3 人、モック、費用なし）。押すとホームに木が現れ、チップが生まれる（§2）。
- **初回の接続画面は出さない。** 接続先が未設定のまま本物の依頼を送ろうとしたとき（Enter）に、`接続先` のダイアログ（既存の `LiteLlmForm`）をその場で出す。`あとで` で閉じて、依頼はモックで送る。設定からも開ける（従来どおり）。
- 下書き画面（Ctrl+N）は空のホームと同じ部品（`HomeComposer center`）にする。送ると会話を開く。

### 4.1 計画カード

監督役の会話で、連続するツール呼び出しが `session.spawn` を含むとき、その `tools` ブロックは `PlanCard` になる。

```
┌ ◆ 5 人に任せる                                                    ┐
│   互いに待ち合わせずに進められる作業なので、同時に任せます。            │  ← 決定の理由（recordDecision があれば）
│ ◉ 競合 3 社の調査   競合 3 社の価格と主な機能を調べ、出典をつけて…  ○2 │  ← 子ごとに 1 行：状態・題・依頼の 1 行・完了条件の数

│ ✋ FAQ を 10 問つくる  問い合わせが多そうな質問 5 つと回答を…       ○1 │
│ ⚠ 配信リストの整理   …                                        ⑂ ○1 │  ← 作業場所がコードなら枝のアイコン
│ ✓ プレスリリース案   …                                           ○1 │
└───────────────────────────────────────────────────────────────────┘
```

- 行の状態は、`session.spawn` の結果の `session.id` から木（`useSessionTree`）の子を引く。結果がまだなければ `queued` の形。押すとその子へ。

- spawn 以外の呼び出し（`recordDecision` 以外）が混ざるときは、計画カードの下に従来の `ToolGroup`。
- 監督役の本文（「5 つに分けて任せます。」）はそのまま上に残る。

## 5. 漏れの掃除

- **モデル名**：子の会話（`parentSessionId` あり）では入力欄のモデルピッカーを出さない。根の会話では残す。
- **タイムライン**：読み込み中は 3 行の骨組み（`Skeleton`）。
- **費用のポップオーバー**：モデル別の行は `mock/` などの提供元の前置きを外して表示。
- **サイドバー**：プロジェクトの木が 1 本だけで、その題がプロジェクト名と同じなら見出しを出さない（繰り返しに見える）。ほかは従来どおり。

## 6. 右腕（次の段。今回は作らない）

ホームの入力欄に打ったものを、権限を持つメタ LLM が受ける。新しい仕事なら会話を作って任せる、「今何してる？」なら答える、「ログイン改善は止めて」なら操作する。答えは入力欄の直上に 1〜2 行。Core Daemon 側に「全部の木を見渡せる会話」とその権限（spawn / stop / resume / send / list）が要るので、§1〜5 の手応えを見てから仕様を切る。
