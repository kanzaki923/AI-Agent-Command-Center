# 2026-10-30 右腕のコンテキストを軽くした（ツール定義と履歴の覚え方）

`20261030_right-hand-real.md` の「1 回の入力が 10k〜34k トークン」の続き。金額より、会話が長くなるほど膨らむ構造を直した。

## 何が重かったか（実測、右腕の 19 ツール）

| | 文字数 |
|---|---|
| ツール定義（説明＋JSON Schema） | 15,169 → **10,900**（−28%） |
| system prompt（役割＋状況、木なし） | 1,876 |

重かったのは説明文ではなく Schema：id の正規表現が 30 回、`once` の日時正規表現が 300 字、`session.send` の content に人が送れない `reasoning` / `tool_call` / `tool_result` の定義、ページングの引数。これらは検証にしか使わず、検証はディスパッチャが zod でやり直す。

もう 1 つは履歴。普通のチャットなので、過去の実行のツール往復（Session や Schedule の JSON 丸ごと、`home.get` の全部の木）が毎回送り直されていた。これは無駄というより**古い**（状況は system prompt の `statusBlock` が正）。

## 直したこと

1. **`stripValidationKeys`**（`llm/tools.ts`）：ツール用 JSON Schema から `pattern`・長さ・範囲・要素数を落とす。全エージェント共通。
2. **`session.send` の content** は文字列か text の部品だけ（契約）。
3. **`rememberPastRuns`**（`assistant/history.ts`）：右腕は過去の実行を「言ったこと」で覚える。ツール呼び出しは assistant メッセージの中の 1 行 `[method 引数 → ok id=… title=… / error: …]`、tool メッセージは送らない。いまの実行の往復はそのまま。
4. **system prompt を 2 つに**：先頭は変わらない役割（tools と合わせてキャッシュの接頭辞になれる）、2 つ目が hint と状況。
5. 右腕のプロンプトと矛盾していた説明文 2 つ（`session.tree` の「これで状況を答えろ」、`cost.summary` の「agent は自分の木だけ」）を削除。

## 効果（本物の Haiku 5.5、同じ 7 つの言葉）

| 往復 | 呼び出し | 入力トークン 前 | 後 |
|---|---|---|---|
| 新しい仕事を立てる | 2 | 18,624 | 12,627 |
| 今どう？ | 1 | 9,717 | 6,305 |
| Excel の質問 | 1 | 9,801 | 6,455 |
| フォルダのヒントつき | 2 | 20,563 | 14,011 |
| 止める | 2 | 21,335 | 14,052 |
| 繰り返しを作る | 3 | 34,280 | 22,932 |
| 再開して一言 | 2 | 24,889 | 15,260 |

右腕の費用 $0.015 → $0.011。1 回の呼び出しは「約 6k ＋ 会話の文」でほぼ一定になり、7 往復目でも 1 往復目と同じ重さ。振り分けと返事の質は変わらなかった（同じ 7 つの判断、同じ文面）。

## プロンプトキャッシュについて

- 1 回の実行の中では履歴は追記だけなので、1 往復で 2〜3 回呼ぶときの接頭辞は崩れない。実行をまたぐときは状況ブロックが変わるので、履歴を畳んでも失うものはない。
- 本当に効かせるには `cache_control` を先頭の system ブロックに付ける必要がある。LiteLLM 経由なら通るはずだが未確認。Anthropic の OpenAI 互換エンドポイントでは付けられない前提。Gateway には入れていない。

## 残っていること

- `schedule.create` / `update` の `run` の入れ子は契約そのもの（各 1,700 字）。触っていない。
- 監督役にも同じ覚え方を適用するかは、右腕での手応えを見てから。監督役は `contextMessages`（40 件）と木のスナップショットで別の形で抑えている。
- `cache_control` の付与（LiteLLM 経由で実測してから）。
