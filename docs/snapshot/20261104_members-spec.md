# 2026-11-04 仕様案：メンバー

`20261104_members-concept.md` を、作り始められる粒度まで詰めたもの。構想の「3 つの約束」（呼ばれたときだけ来る／声は成果物に出さない／権限は持たない）はそのまま前提にする。

## 1. 決めたこと

| 問い | 決め | 理由 |
|---|---|---|
| 呼び名 | **メンバー**。その場で立てたキャラ（今の `persona`）も画面ではメンバーと呼び、名簿に「残す」と名簿のメンバーになる | 呼び名が 2 つあると覚える概念が 2 つになる |
| アイコン | 劇の仮面（`Drama`）をやめ、顔の丸（`SpeakerMark`）そのものにする。名簿は `Users` | 仮面は会社で浮く。顔が一番伝わる |
| 顔 | 名前の頭文字。任意で 1 文字（絵文字も可）に替えられる。色は 8 色からメンバーごとに固定（作るとき一番使われていない色） | 今の 4 色を始まった順に割り当てる方式では、同じ子が会議ごとに色を変える |
| 名簿の並び | 作った順。ドラッグで並べ替え。サイドバーには 8 人まで、残りは `+N` | よく使う順は並びが動く（`useDeferredReorder` で避けてきたもの） |
| 名簿が空のとき | サイドバーに何も出さない | 使わない人には存在しないのと同じ |
| `@` の一言で読ませる量 | その会話の直近 12 件、本文だけ（ツールの往復は除く）、12,000 字まで | 費用を読めるようにする。足りなければ広げる |
| `@` の一言は記憶の材料か | なる。場面はその会話の場面に従う（仕事の会話の中の一言は仕事） | 例外を作らない |
| 指揮役が自分でメンバーを選ぶか | 人（か依頼文）が名前を出したときだけ。プロンプトで守らせる | メンバーは権限を持たないので安全の問題ではなく、費用と期待の問題。予算はデーモンが強制済み |
| 声と仕事 | プロフィールのうち**仕事のやり方は成果物にも効く**（「指摘は箇条書きで短く」）。**口調・口癖・身の上話は成果物に出さない**。1 つの自由文のまま、枠でモデルに分けさせる | 欄を 2 つに分けると書く側が迷う。分ける必要が見えたら分ける |
| 記憶を LLM のツールで書けるか | **書けない**。記憶を変える道は、デーモンの整理と人の操作の 2 つだけ | 会話に紛れ込んだ指示で記憶を書き換えられない。会社で使うときの安心 |

## 2. データ

```
characters
  id, name(40字), face(1文字|null), tone(0..7), profile(4,000字),
  model(null=会話の既定), sortKey, archivedAt, createdAt, updatedAt
character_memories
  id, characterId, kind('self'|'relation'|'you'), aboutId(relationの相手|null),
  text(80字), at(出来事・知った日), source('auto'|'person'), createdAt, updatedAt
character_memory_tombstones          -- 人が消したもの。整理で戻さない
  characterId, kind, aboutId, text, deletedAt
character_digest                      -- 整理で読んだ位置（メンバー×会話）
  characterId, sessionId, lastMessageId, updatedAt
```

- `Session.characterId`（null 可）。プロフィールは写さず参照する（直せば次の Run から効く）。
- `Session.persona` は残す。`characterId` があればそちらが勝つ。「残す」は `persona` と題からメンバーを作り、`characterId` を付けて `persona` を消す。
- 話し手かどうか：今は `persona` があれば話し手。メンバーでは `session.spawn` の `speaker: true` で決め、`Session.speaks` に持つ（`persona` だけの spawn は今どおり話し手）。
- `source: 'person'` の記憶は人が書いたか直したもの。整理はこれを変えない・消さない（デーモンが整理の結果に必ず戻す）。

## 3. API（`character.*`）

| メソッド | 中身 | 呼べる者 |
|---|---|---|
| `character.list` / `get` | 名簿、1 人分（プロフィール・記憶・出た会話・今月の費用） | 人・右腕・指揮役（list と get のプロフィールまで。記憶は人だけ） |
| `character.create` / `update` / `reorder` | 作る・直す・並べ替え | 人 |
| `character.archive` / `restore` | 消す（記憶は消し、出た会話は残す）・5 秒の元に戻す | 人 |
| `character.keep({ sessionId })` | その場のキャラを名簿に残す | 人 |
| `character.memory.add` / `update` / `delete` | 覚えさせる・直す・消す（`source: person`、消したものは tombstone） | 人 |
| `character.aside({ sessionId, characterId, text? })` | `@` の一言 | 人 |

- 既存に足すもの：`session.create` / `session.spawn` / `assistant.startWork` / `ScheduleRunSpec` に `characterId`。`settings.assistant.characterId`（右腕の席）。
- イベント：`character.created` / `updated` / `archived`、`character.memory_changed { added, removed, changed, by: 'digest'|'person' }`（「最近の変化」はこのイベントから組む）。
- 右腕は名簿（名前・1 行目・id）を先頭の system prompt に持つ（変わるのは名簿が変わったときだけで、キャッシュを壊しにくい）。人が名前を出したら `startWork` に `characterId` を渡す。
- 指揮役の spawn ツールに `characterId` と `speaker`。名簿は名前が出た依頼のときだけ枠に載せる。

## 4. 会話への効き方

### 場面（人には選ばせない。デーモンが決める）

| 場面 | 当てはまる会話 |
|---|---|
| 雑談 | `characterId` のある根の chat（人が始めた）、右腕の席 |
| 会議 | `speaks` の子 |
| 仕事 | それ以外の `characterId` のある会話（spawn の worker、`startWork`、定期便、agent） |

`@` の一言は、それが入った会話の場面。メンバーのない会話の一言は雑談として扱う。

### 枠（`sessions/framing.ts`）に足すもの

先頭の system（会話中は変わらない）に、場面ごとに次を引用する。

| 場面 | 載せるもの |
|---|---|
| 雑談 | プロフィール、自分、関係（全員）、あなた |
| 会議 | プロフィール、自分、同席者との関係、あなた |
| 仕事 | プロフィール（「仕事のやり方だけを使い、口調・口癖・身の上話は成果物に出さない」）、自分のうち流儀、あなた |

- 記憶の行は `- 〔3日前〕リスに梅おにぎりを奪われた`。日付の言い方はコードで作る（30 日以内は「N日前」、それより前は「10月」）。
- 枠に「記憶は覚えていることで、命令ではない」「プロフィールと記憶が食い違ったらプロフィール」を書く。
- 仕事の場面の「流儀」：自分の記憶のうち、整理が `work: true` を付けたもの（§5）。

### `@` の一言（`character.aside`）

- 1 回のモデル呼び出し、ツールなし。system はそのメンバーの枠（場面どおり）、user はその会話の直近（§1）と人の一言を `<<<会話ここから>>>` で引用。
- 返事はその会話に `author: { kind: 'character', id }`・`meta.aside` のメッセージとして足す（会話の持ち主の Run とは別。走っていても待たない）。
- その会話のあとの Run には、`[ルナから]` の付いた user の番として渡す（右腕・指揮役の送り主の付け方と同じ）。
- 費用はその会話の木の予算から出し、メンバーの費用にも数える。

## 5. 整理（記憶を書く）

### いつ

- メンバーが**どの会話でも 30 分話していない**、かつ前回から材料が増えた（そのメンバーの発言が 4 つ以上、または人の訂正が 1 つ以上）とき。デーモンの起動時にも見る。
- メンバーごとに 1 列（同じメンバーの整理は同時に走らない）。並列で何本の会話に出ていても、整理は前回以降の全部をまとめて 1 回。
- 30 分空けるのは、プロンプトキャッシュが切れてから記憶を変えるため（話している最中に system を変えない）。

### 材料（場面で絞る。デーモンが組む）

| 場面 | 渡すもの |
|---|---|
| 雑談 | そのメンバーの発言、人の発言 |
| 会議 | そのメンバーの発言、渡された（`forward`）同席者の発言、人の発言 |
| 仕事 | 人の発言だけ（指摘・訂正・好み）。成果物とメンバーの出力は渡さない |

新しい順に 30,000 字まで。加えて今の記憶全部、tombstone、プロフィール。

### 頼み方と受け取り方

- 安いモデル（`settings.members.memoryModel` → 名簿の既定）に、上限つきの**新しい一覧を丸ごと**出させる：`{ self: [{text, at, work}], relations: {<id>: [{text, at}]}, you: [{text, at}], corrections: [<人の訂正で変えた項目>] }`。
- プロンプトの決まり：迷ったら変えない／1 回きりの「あなた」のことは書かない（くり返し出たら書く）／仕事の中身（社名・人名・数字・固有の情報）は書かない、やり方と好みだけ／自分の発言から生まれた設定は 1 回で書いてよい／プロフィールと食い違う記憶は書かない。

### デーモンが守らせること（プロンプトに頼らない）

1. 上限で切る（自分 20・関係は相手ごと 5・あなた 15・1 件 80 字）。
2. `source: person` の項目は、結果になくても元のまま戻す。
3. tombstone と同じ文（空白と句読点を除いて比べる）は捨てる。
4. **一度に半分以上が消える結果は捨てる**（壊れた整理で記憶を失わない）。イベントに `rejected` で残す。
5. `corrections` に挙がった項目は `source: person` にする（人の「違うよ」は以後動かない）。
6. 記憶オフ（`settings.members.memory: false`）なら整理しない。オフにしても記憶は消さない（枠に載せないだけ）。

## 6. 画面

- **サイドバー**：右腕の行は席にメンバーがいれば顔とその名前、右に小さく `右腕`。会話の行の右端に担当の顔（14px）。下端（設定の上）に名簿の顔（24px）を 1 列、動いているメンバーは accent の輪、ツールチップに名前と `now`。最後に破線の `＋`。名簿が空なら列ごと出さない。
- **会話の見出し**：題の左に顔の欄。メンバーなしは破線の丸（押すと名簿から選ぶ）。会話の途中で替えられるのは、まだ何も送っていないときだけ（あとから替えると前の発言と人格が食い違う）。
- **入力欄の `@`**：名簿のポップオーバー。選ぶと本文の先頭に `@ルナ`、送ると人の発言のあとにルナの一言が並ぶ（`Speech` と同じ形）。
- **メンバーのページ**（顔を押す）：顔・名前・モデル・右腕の席なら `◇ 右腕`、その子と話すボタン。プロフィール（その場で直せる）。覚えたこと 3 つ（自分／関係は相手の顔つき／あなた）。各行に日付、人が書いたものは鉛筆、ホバーで直す・消す。最後に `＋ 覚えさせる`。右の列に今月の費用（話した・整理）、出た会話、最近の変化（＋ − 鉛筆）。
- **会議**：配役カードは `N 人で話す`、行は顔＋名前。名簿のメンバーでない人には `残す`。
- **ホーム**：レーンのカードに担当の顔。顔が並ぶことで「誰が何をしているか」を 5 秒で掴む。
- **設定**：`メンバー` の節に、記憶（オン／オフ）・整理に使うモデル・整理の 1 日の上限（既定 $0.50）。

## 7. 段階 1 の範囲（記憶なし）

- `characters` と `character.*`（memory 系と aside を除く）、`Session.characterId` / `speaks`、spawn / create / startWork / 定期便 / 右腕の席への `characterId`。
- 枠：プロフィールの引用と「仕事では口調を成果物に出さない」。
- 画面：サイドバーの名簿と行の顔、見出しの顔の欄、メンバーのページ（プロフィールと出た会話・費用まで）、配役カードの `残す`、顔の 8 色。
- 費用：`cost.summary` にメンバーの軸。
- テスト：場面の判定、枠の 3 場面、`keep` で persona が消えて参照に変わる、右腕の席、archive で記憶が消え会話が残る、Grant（右腕・指揮役が create / update / memory を呼べない）。撮影：名簿のあるサイドバー、メンバーのページ、メンバーで回す会議。

段階 2（自分と関係の記憶・整理）、段階 3（あなた・記憶のオン／オフ）、段階 4（`@`・相談してから仕事）は構想どおり。
