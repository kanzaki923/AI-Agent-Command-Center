# 2026-10-30 右腕の仕様（ホームの入力欄をメタ LLM が受ける）

`20261030_ui-rework-spec.md` §6 の「次の段」を切る。前提は §1〜5 が入った状態（`e6b21ec` 以降）。構想は `concept.md` §1.3・§2・§3、源泉の言葉で言えば「普段のチャットで相談していた AI に、必要な権限を与えるだけで、ほかのエージェントを指揮して仕事を進めてもらえる」「こっち側に LLM が立てる」。

## 0. 何が変わるか（ユーザ目線）

いまのホームの入力欄は「新しい会話を作る」装置で、任せるかどうか（◇）・どこで働くか（作業場所）を人が決めてから送る。右腕が入ると、入力欄は**ひとりの相手に話しかける欄**になる。

| 打つもの | いま | 右腕のあと |
|---|---|---|
| 来月のローンチ準備を進めて | ◇ をオンにして送る → 新しい木 | 右腕が木を立てる。欄の上に「5 人で始めます」。レーンが生まれる |
| 今どう？ | （聞けない） | 「出番が 3 件。ローンチ準備は 2/5、配信リストが失敗」 |
| ログイン改善は止めて | サイドバーから会話を開いて ■ | 右腕が止める。「止めました。再開は言ってください」 |
| 毎朝 9 時に昨日のまとめを作って | 会話を作ってから ⟳ を設定 | 右腕が繰り返しを作る。「毎朝 9:00。最初は明日」 |
| Excel で A 列の重複を消すには？ | 新しい会話（答えは会話の中） | 右腕がその場で答える。長くなれば会話として開ける |

人が覚える操作は減る（◇ が消える）。右腕にできることは Core Daemon の権限で縛る（プロンプトでは縛らない。`CLAUDE.md`）。

**合格基準**：一言頼んだあと 10 秒で「チームが動き出した」と感じる（レーンが生まれる）。状況を聞いたら 1〜2 行で返る。止めろと言えば止まる。右腕が勝手に出番に答えることはない。承認依頼は 0。

## 1. 右腕とは何か（Core Daemon）

右腕は**権限を持った 1 本の会話**（`kind: 'chat'`）。既存の仕組みそのまま：権限（grant）を持つ chat は、その権限が許すメソッドをツールとして受け取り、アプリの操作主体になる（`sessions/chat.ts`、`apiTools`）。右腕のために新しい実行エンジンは作らない。

- **1 つだけ**。デーモンが初回に作り、`system.assistant` が `{ sessionId }` を返す（なければ作る）。アーカイブ不可。
- **役割**：`SessionRole` に `assistant` を足す（`ext/home.ts`）。ホームの木には入れない（`home.get` の trees から除外。右腕は働き手ではなく「あなたの隣」）。サイドバーのプロジェクト分けにも入れない。
- **モデル**：`settings.assistant.model`（未設定なら `defaultModel`、LiteLLM 未設定なら `mock/right-hand`）。
- **システムプロンプト**：役割（人の隣に立ち、木を見渡し、新しい仕事は木を立てて任せる、聞かれたら短く答える、言われたら操作する）、言葉のトーン（`ui-design` §9：短く、断定、1〜2 行）、やってはいけないこと（出番に代わりに答えない、人の言葉を言い換えて子に渡さない）。文面は `orchestrator/` の監督役プロンプトと同じ場所で管理する。
- **会話の文脈**：毎回のターンに、ツールを呼ばなくても状況が分かるよう `home.get` の要約（木ごとに 1 行：題・進み具合・出番・失敗）を system に差し込む。これで「今どう？」は 1 回のモデル呼び出しで返る。

### 1.1 権限（grant）

主体 = 右腕のセッション、`lifetime: 'session'`、`depth: 0`、`grantedBy: system`、`scope.projectIds: null`（全プロジェクト）。

| 許す | 理由 |
|---|---|
| `home.get`（`tool: true` に変える）、`session.list` / `get` / `tree` / `messages` / `search`、`project.list` / `get`、`cost.summary`（`tool: true` に） | 見渡す |
| `assistant.startWork`（新設、下） | 新しい木を立てる |
| `session.send` | 木の根（監督役）に言葉を渡す（「FAQ は 5 問でいい」） |
| `session.stop` / `session.resume`（`tree: true` 可） | 止める・再開する。どちらも戻せる |
| `schedule.preview` / `create` / `update` / `delete` / `list` / `get` | 繰り返し |

| 許さない | 理由 |
|---|---|
| `attention.respond` / `dismiss` | 出番は人のもの。右腕が代わりに答えたら「安心して任せる」が壊れる |
| `session.archive`、`session.setBudget`、`cost.raiseDaily`、`settings.*`、`project.create` / `update`、`system.*` | 戻しにくい、または人の持ち分 |
| `session.spawn`（自分の子を作る） | 右腕の下に木ができるとホームが 1 本のレーンに潰れ、並列の把握が崩れる。木は常に根として立てる |

上限（`GrantLimits`）：1 メッセージで立てる木は 3 本まで（`assistant.startWork` が数える）、右腕自身のモデル費用は `settings.assistant.dailyUsd`（既定 $2）。立てた木の予算は、人がホームから任せたときと同じ既定（任せ方の設定）。右腕の予算からは削らない。

### 1.2 `assistant.startWork`（新設メソッド。人も呼べる）

いまの UI の `startConversation`（create → delegate → send）をデーモンに下ろしたもの。

```
params: { text, title?, delegate = true, projectId?, workspace?, model? }
result: { session }   // 新しい根
```

- `title` がなければ `text` の 1 行目から（UI の `titleFromRequest` をデーモンへ移す）。
- `delegate: true` なら `session.delegate` を既定値で当て、`text` を最初の人のメッセージとして送る（`author` は **人**。右腕が人の言葉を運んだだけで、言い換えてはいない。`HomeTree.goal` に人の言葉が出る）。
- 右腕が呼んだとき、新しい根の `startedBy` は `assistant`（`ext/home.ts` の enum に足す）。レーンの見出しの役割アイコンに小さな右腕の印（繰り返しの時計と同じ位置）。
- 右腕が `delegate: false` で呼ぶのは、人が「〜のモデルで話したい」「ブログ記事を書いて」のように、ひとつの会話で済むとき。

### 1.3 モック（`mock/right-hand`）

デモと撮影とテストのため。入力の形で分ける：

- 末尾が `？` / `?`、または `今` / `どう` / `何` で始まる → `home.get` を 1 回呼んで、出番の数・木ごとの進み具合・失敗を 1〜2 行。
- `止めて` / `止めろ` / `停止` ＋ 木の題（部分一致） → `session.stop {tree: true}`。`再開` も同様。
- `毎朝` / `毎日` / `毎週` ＋ 時刻 → `schedule.preview` → `schedule.create`。
- それ以外 → `assistant.startWork {delegate: true}`。返事は「「<題>」を始めます。終わったら知らせます」。子の人数は監督役（`mock/orchestrator`）が決めるので、ここでは言わない。

`mock/orchestrator` と同じく、同じ文を 2 回続けて返さない。

## 2. UI

### 2.1 入力欄（`HomeComposer`）

- **◇（任せる）を消す。** 任せるかどうかは右腕が決める。会話の中の「任せる」ボタン（`DelegateButton`）は残す（途中から任せる）。
- 作業場所の切り替え（なし / フォルダ / コード）は残す。選んだものは `assistant.startWork` の `workspace` / `projectId` の**ヒント**として右腕に渡す（system に 1 行）。
- Enter：右腕に `session.send`。送った瞬間に欄が空になり、欄の上に自分の言葉が 1 行（`text-fg-3`）と、右腕の印が呼吸する。返事が流れ込む（§2.2）。Ctrl+Enter：送って右腕の会話を開く。
- 接続先の聞き方は今のまま（未設定で最初の依頼 → ダイアログ、`あとで` でモック）。
- 空のホーム・Ctrl+N の下書きも同じ欄。例の 1 行と `試してみる` はそのまま。

### 2.2 右腕の声（`AssistantLine`、新）

入力欄の直上、レーンの下。**最後のやりとり 1 往復だけ**。

```
│ ◆ ログイン改善 …（レーン）                                          │
│                                                                     │
│   来月のローンチ準備を進めて                                        │ ← 自分の言葉（text-fg-3、1 行）
│ ◇ 「新製品ローンチ準備」を始めます。終わったら知らせます。     開く › │ ← 右腕（text-fg、最大 2 行、流れ込む）
│ ◇ 何を頼みますか                                         [▢][📁][⑂] │
```

- 右腕の返事は `ChatStream` と同じ流し込み（§6.1）で、最大 2 行（それ以上は `…` と `開く`）。
- ツールを呼んでいる間は、返事の代わりに右腕の印が呼吸する。文字で「考え中」とは書かない。
- 右腕が木を立てたら、レーンは `session.created` → `home.get` で生まれる（生まれる動き、§3 の 3 場面の 1 つ目）。返事の中の題は押せる（そのレーンへ）。
- 次の入力で前の往復は消える。何も話していない起動直後は何もない。
- `開く`：右腕の会話（普通の会話画面。履歴全部、モデル切替可）。
- 右腕の会話への入口はもう 1 つ：サイドバーの固定行（ホーム / 右腕 / タイムライン）。右腕の会話には未読の点もつく。

### 2.3 見た目の決め

- 右腕の印は `Diamond`（任せた会話と同じ菱形）を塗りなしで。色は `--st-supervising` の紫。働いている間は `acc-breathe`。
- 右腕が立てた木のレーン：役割アイコンの右下に 7px の菱形（繰り返しの時計と同じ扱い）。ツールチップ「右腕が始めた」。
- 右腕の費用は費用の内訳に「右腕」の行として出る。チップやレーンには出ない。

### 2.4 消えるもの・残るもの

- 消える：ホームの ◇。`Draft`（Ctrl+N）の ◇。
- 残る：会話の中の `DelegateButton`、`RepeatButton`、作業場所の切り替え、`試してみる`。
- 変わる：`startConversation`（UI）は `assistant.startWork` を呼ぶだけになる（デモの `startDemo` も）。

## 3. 安全と上限（Core Daemon が強制）

- 権限は §1.1 の表のとおり。ツール一覧は grant から生成されるので、プロンプトに書かなくても出番に答える道はない。
- 1 メッセージで立てる木は 3 本まで。超えたら `assistant.startWork` が拒み、右腕は「3 本まで。残りは分けて言ってください」と返す。
- 右腕の日次上限（`settings.assistant.dailyUsd`）に当たったら、右腕は返事をせず、欄の上に「右腕は今日の上限に当たりました」（これは UI の文言。例外的に文字で出す）。設定の「1 日の上限」の隣に「右腕」の行。
- 右腕が立てた木が出番を出したら、それは人に来る（ホームの出番の列）。右腕には `child_update` は来ない（子ではないので）。右腕が状況を言うときは毎回 `home.get` を見る。

## 4. 作る順番と持ち分

1. **Core Daemon**（見えない部分。エージェントに任せてよい）：`SessionRole.assistant`・`startedBy: 'assistant'`、`system.assistant`、`assistant.startWork`、grant の組み立て、`home.get` / `cost.summary` の `tool: true`、system への状況要約、`mock/right-hand`、`settings.assistant`。テスト：権限の表（許す・許さないを両方）、3 本の上限、startWork が根を作り人の言葉を最初のメッセージにすること、モックの振り分け。
2. **UI**：`HomeComposer` の送り先、`AssistantLine`、サイドバーの固定行、レーンの印、費用の内訳の行、`startConversation` の置き換え。撮影の場面に「右腕に頼んだ直後」「今どう？の返事」を足す。
3. **あと**：右腕が自分から話す（木が全部終わった・失敗が続いた）。監督役の `inbox` の仕組みを右腕にも広げるかを、2 までの手応えで決める。

## 5. 決めていないこと

- 名前。「右腕」は作業名。UI の固定行の文言は決めるときに `ui-design` §9 に足す。
- 右腕の会話が長くなったときの履歴の切り方（`CHAT_HISTORY_LIMIT` 200 のまま始める）。
- 右腕に「このプロジェクトの話」と限定する方法（当面は作業場所のヒントで足りるとみる）。
