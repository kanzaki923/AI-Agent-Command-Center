# 2026-11-05 引き継ぎ：v0.1.2 プロジェクトの会話がファイルを読めるように

v0.1.1 を入れて「プロジェクトで開発したい」と使ってみたら、会話がファイルを読めなかった。穴が 2 つ重なっていた。

## 直したもの

- **エージェントが黙ってモックだった**：実行基盤の既定（`settings.defaultRuntime: null`）がモックで、画面から変えられなかった。null を「自動」にして、デーモンのプロセスが Claude Code の CLI を見つければ `claude-agent-sdk` で動かす（`RuntimeRegistry` の `detect`、`main.ts` の `detectAgentRuntime: true`）。
  - テストとスクリプトの `createDaemon` / `startDaemon` は検出しないので、自動はいつもモック。テストで本物のエージェントに届かない。
  - モックのモデル（`mock/*`）の会話と、モックのモデルの親が起こす子はモックのまま。デモはオフラインのまま。
- **設定に「エージェント」の行**：`Claude Code` / `モック`。ツールチップに、どの道で動くか（LiteLLM・Anthropic のキー（従量課金）・手元のログイン）。見つからないときは選べず、理由を出す。`settings.get` / `settings.update` が `agentRuntime` を返す。
- **新しい会話の作業場所の既定**：プロジェクトを選ぶと、そのプロジェクトの場所（コード、なければフォルダ）で始まる（`defaultPlace`）。今までは「なし」で始まり、プロジェクトの名前がついているのにファイルが見えないチャットになっていた。
- 全体のテストで、重い `outputs.test.ts`（500 ファイル）が 5 秒を超えることがあったので、そのテストだけ 20 秒にした。

## 確かめたこと

- `pnpm check` 緑（1,460 件）。
- 別の `ACC_HOME`・ポートで本物のデーモン（`pnpm start:daemon`）と画面（Vite）を立てた。
  - 設定は何もしない状態で `エージェント` が `Claude Code`。
  - このリポジトリをプロジェクトにして、作業場所をコードにした会話に README のことを聞いた。Claude Code が `Read` で読んで正しく答えた。
  - 新しい会話でプロジェクトを選ぶと、作業場所が `コード` になる。

## 残っていること

- 新しい会話は、今のプロジェクト（`ui.projectId`）がなければ「プロジェクトなし」で始まる。プロジェクトが 1 つしかなくても自動では選ばない（雑談まで worktree のエージェントになるのを避けた）。使ってみて迷うなら再考する。
- ホームの欄（右腕）の作業場所は今までどおり `自動（右腕が決める）`。
- 実行基盤は Run ごとに解決して、会話にも Run にも記録しない（`runtime: null`）。設定を変えると、既存のエージェントの会話も次の実行から変わる。
