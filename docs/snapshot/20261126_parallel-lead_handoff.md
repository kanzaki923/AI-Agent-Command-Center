# 2026-11-26 引き継ぎ：コードの会話から並列に分ける（リード）

使ってみたら、コードの会話で「worktree を分けて別セッションで作業して」と頼んでも断られた。Claude Code が `git worktree` を打ち、デーモンの絶対ルール（git のメタデータ）で止まっていた。人が始めたエージェントの会話には子を立てるツールもなく、並列に分ける入口はホームの欄（右腕）と、チャットの会話の「任せる」だけだった。

やりたいことは「並列でタスクを終わらせる」。worktree はその手段なので、デーモンが管理したまま賢く使えるようにした。

## 作ったもの

- **リード**：親のないエージェントの会話がリポジトリのあるプロジェクトの worktree で動くと、実行の始まりにデーモンが指揮役の権限を付ける（`ensureLeadGrant`）。ボタンはない。
  - そのプロジェクト限定、子は同時に 4 まで、深さ 1、予定は作れない。
  - 予算は作らない。今日の上限で止まる（会話だけのときと同じ）。
  - ツールは Grant から作るので、最初の実行から `session_spawn` などが渡る。前提には「並列に分けるとき」の段落が入る。
- **子の worktree は親の今から**：親が `baseRef` を書かずに子を起こすと、デーモンが親の途中の変更をコミットし、親のブランチから子の worktree を切る。
- **起こされる**：子が終わると、親の Claude Code が `[状況の更新]` で起こされる。これは既存の受信箱が、エージェントの会話をエージェントの実行として起こす作りになっていたので、そのまま動いた。
- **まとめる**：`integration.create` に `sessionIds` を足した（子、最後に自分）。
  - agent が指定できるのは自分の木の会話だけ。
  - 子の worktree は Task を名指さないので、会話から Task を引く。反映で子の Task が done になる。
  - 呼び出し元の実行が使っている自分の worktree も、コミットしてから含める。
- **間違った道を塞いで案内する**：`git worktree` と `isolation: "worktree"` のサブエージェントは断る。理由には「`session_spawn` で子を立てて」と添える。

## 確かめたこと

- `pnpm check` 緑（1,495 件）。
- `orchestrator/lead.test.ts`（モックのランタイム）で次を確かめた。
  - 最初の実行からツールと前提が渡る。
  - 子・チャット・フォルダには付かない。
  - 子の worktree に親の途中の変更が入り、`baseRef` を書けばそのまま。
  - 子が終わると親がエージェントの実行で起こされる。
  - `sessionIds` で子と自分をまとめられ、自分の木の外は断る。
  - `git worktree` と worktree のサブエージェントは案内つきで断る。

## 確かめていないこと

- **本物の Claude Code が、頼まれたときに実際に `session_spawn` を選ぶか**。前提の文章とツールの説明だけが頼りなので、本物で一度通す必要がある。
- 子が多いときの費用の見え方（予算を作らないので、今日の上限だけが止める）。
- リードの「同時に動かす数」を画面から変える手段はない（既定 4）。
