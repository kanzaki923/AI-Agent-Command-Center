# 2026-10-30 UX レビュー：キラキラはどこで漏れているか

ブランチ `vertical-slice` の画面を、監査の場面（`node apps/desktop/e2e/audit.js --serve`、3 本の木・子 10 人・定期実行・ふつうの会話）で実際に触り、22 枚の撮影も目で見た。内部の実装ではなく、**構想の源泉（壁打ちの Raw 文章）で感じたワクワクが、触って伝わるか**だけを見た。

## 結論

**「見える」は完成している。「任せたくなる・話しかけたくなる」がまだない。**

`20261030_ui-redesign-spec.md` の合格基準「10 人動いている状態を 5 秒眺めて、進捗・問題・出番が分かるか」は、ちゃんと通っている。出番が上に並び、木ごとに子のチップ、状態は色と形。これは良い。

でも源泉のキラキラは「状態が分かること」ではなかった。

- **一言で、チームが動き出す**（「その方針で進めて。空いてる人使っていいよ」）
- **こっち側に立つ AI がいる**（「今何してる？」「テスト担当をもう 2 人追加して」「API 改修は止めて」が、そのまま通る）
- **10 人動いているからこそ、自分は暇になる**（成果物だけが整理されて届く）
- **触っていて気持ちいい**（意味のある動き、サクサク、上品）

いまの画面は、この 4 つのどれも**主役にしていない**。ホームは掲示板（タスクの一覧）になっていて、「率いる」でも「任せる」でもなく「監視する」画面になっている。これが「これじゃない感」の正体だと思う。

## 画面ごとに見えたこと

### ホーム

- **数字が多すぎて、請求書に見える。** 1440×900 のホームに `$` が 14 個、`N秒` が 11 個。チップの 3 行目はすべて「経過秒と費用」で、ストップウォッチとメーターを並べて眺めている感覚になる。源泉での予算は「安心して任せるための柵」で、常時見せる主役ではない。
- **全部が同じ重さ。** 出番の行・チップ・落ち着いた会話の行が、同じ灰色・同じ 12〜13px・同じ枠。どれが大事かは色の点でしか分からない。ざっと見て目が止まる場所がない。
- **目標（自分の一言）がどこにもない。** 「新製品ローンチ準備」という題だけで、「来月 20 日に出す。準備を進めて」と頼んだ自分の言葉は会話を開かないと見えない。木のレーンが「何のために動いているか」を言っていない。
- **計画と進み具合が見えない。** 5 人中 2 人終わった、残りはこれ、終わると何が出てくる、が 6px の帯 1 本。
- **成果物が脇役。** 完了チップに 📄 が 1 個。「暇になれる」理由である「できあがったもの」が、ホームでは一番小さい。
- **何も動いていない。** 5 分眺めて、動いたのは 14px のスピナーだけ。任せた瞬間に子が生まれる、完了して成果物が届く、出番が上に滑り込む——どれも場面として見えなかった（実装はあるかもしれないが、体験として起きない）。
- **入力欄が一番目立たない。** 製品の入口である「何を頼みますか」が、画面最下部の薄い 1 行。左の ◇（任せる）は、押す意味が分からない。

### 監督役（指揮役）の会話

- 「5 つに分けて任せます。」の次が、折りたたまれたツール行「🔧 5 人に依頼 0.6s」。**この製品の一番の見せ場が、ビルドログの 1 行になっている。** 誰に何を、なぜその分け方で、完了条件は何か、が見えない。
- 起床の状況カードも「⚠ 配信リストの整理 ✋ FAQ を 10 問つくる ✓ プレスリリース案」という 1 行で、監督役が「判断した」感じがしない。
- 入力欄の右下に `audit-lead ∨`、子では `assistant ∨`。内部のモデル名が、人格のように見える場所に漏れている。

### 子の会話

- 依頼カードと本文は読みやすい。ここは良い。
- ただし子を「開いて読む」こと自体が、源泉では例外のはず（「必要なときだけ介入」）。子を開かずに済む理由（成果物・出番・いまの作業）がホームで弱いので、結局開くことになる。

### 空のホーム・初回

- 初回画面が **LiteLLM の URL と API キーのフォーム**。アプリの第一印象が設定フォーム。「あとで（モックで試す）」の奥にある 3 人のデモこそ、最初に見せたい場面。
- 空のホームは、暗い画面に薄い入力欄 1 本と、意味の分からないアイコン 3 つ。**この製品に超能力があることが、どこにも匂っていない。**
- 「新しい会話」（Ctrl+N）の下書き画面は、中央に大きな別デザインの入力欄（「プロジェクトなし」つき）。ホーム下端の入力欄と見た目も振る舞いも違う 2 つの入口がある。

### タイムライン・パレット・設定

- タイムラインは切り替え直後 2 秒ほど真っ白（骨組みなし）。壊れたように見える。中身は密なログで、機能としては足りているがワクワクはしない。
- パレットは良い。検索も速い。
- 設定 4 項目＋詳細は良い。費用のポップオーバーに `mock/assistant` が出るのは漏れ。

### 見た目

- 色・字・余白はていねいだが、**暗い管理画面の一般形**で署名がない。チップの面（surface）と地（canvas）の差が小さく、チップが沈んで見える。監督役の紫（supervising）はアイコンの小さな菱形にしか使われておらず、「この木には AI の監督がついている」ことが画面の印象にならない。

## 根本の仮説

直前の作り直し（`ui-redesign-spec` §0）は、「文字で説明しない」「開かずに分かる」を徹底して**状態の可読性**に最適化した。それは成功した。

一方で源泉のキラキラは **レバレッジ（一言 → チームが動く）** と **相棒（こっち側に立つ AI と話せる）** にあった。掲示板はどちらも表現できない。UI の説明文を消すのは正しいが、**AI の声まで消してしまった**のが行き過ぎだったと思う。「残り 3 件は順調です」という UI の要約文は不要。でも「3 つに分けます。FAQ だけ価格の判断が要るので先に聞きます」という **監督役の判断の言葉** は、UI の説明ではなく製品の中身で、これこそ見せたいもの。

## 改修の手がかり（優先順）

### 1. ホームの入力欄を「新規作成フォーム」から「右腕との対話」にする

源泉 §3.2 そのもの。「何を頼みますか」に打ったものを、権限を持つメタ LLM が受ける。

- 新しい仕事なら、会話を作って任せる（いまの動き）。
- 「今何してる？」なら、その場で答える。
- 「ログイン改善は止めて」「テスト担当をもう 2 人」なら、その場で操作して結果を返す。

これで「こっち側に AI が立っている」ことが、最初の画面で体験になる。◇ のトグルは要らなくなる（任せるかどうかは右腕が判断し、必要なら聞き返す）。答えは入力欄の直上に 1〜2 行で出て、消える。

### 2. 「任せた瞬間」を製品のクライマックスにする

- 会話側：「5 人に依頼」の折りたたみ行をやめ、**計画カード**にする。子ごとに題・依頼の 1 行・完了条件・作業場所・予算を並べ、なぜこの分け方かの 1 行（監督役の決定文）を添える。
- ホーム側：任せた直後、レーンが現れて子のチップが 1 枚ずつ（60ms ずらし）生まれる。レーン見出しの下に、**自分が頼んだ一言**を薄く 1 行出す（題の下、省略つき）。
- 子が終わるたびに、レーンの進み具合が「2 / 5」と成果物のアイコン列で見える。帯だけにしない。

### 3. チップを「タスクの行」から「働いている人」にする

- 3 行目の「秒 + $」を既定で消す。見せるのは **いまの作業（`now`）** と、終わっていれば **成果物**。費用はレーン見出しに 1 つ、しかも予算の半分を超えたときだけ色がつく。経過時間は「長すぎる」ときだけ（例：同じ `now` が 5 分以上）出す。
- 作業中のチップは、呼吸する（面がごく薄く明滅する、または `now` の変化時に 1 回光る）。「生きている」感じは、スピナーではなく面で出す。
- 子に軽い個性を与える：題の頭に 1 文字のモノグラム、または木の中で割り当てる固定の色相。10 人が「10 個の行」でなく「10 人」に見える最小のしかけ。やりすぎると下品になるので、まず 1 つ試す。

### 4. 成果物をホームの主役の一つにする

- ホームの出番の列と対になる **「できたもの」の列**（または右端の細い帯）。完了した成果物が、題・種類・どの木から・採用ボタンつきで並ぶ。見たら消える（既読）。
- 「10 人が動いているから暇になる」の報酬が、ここで見える。

### 5. 最初の 1 分を作り直す

- 起動直後は空のホーム。入力欄のプレースホルダに、**任せたときに起きること**を例で見せる（「来月のローンチ準備を進めて」→ 薄く「5 人に分けて任せます」）。説明文ではなく、例。
- その下に「試してみる」1 つ。押すと既存のデモ（3 人）がその場で動き出す。接続先の設定は、本物のモデルを使おうとした最初のときに聞く（初回画面を設定フォームにしない）。
- 下書き画面とホームの入力欄を 1 つに統一する。

### 6. 見た目に署名を入れる

- 監督役の紫を「木が生きている印」にする：子が動いている間、レーン見出しの菱形がゆっくり呼吸し、見出し行の左端に細い紫の線。
- チップの面を地より 1 段明るく（いまは差が小さく沈む）。基本の字を 13px → 14px、チップの題は 600。
- 動きの最低限 3 つを確実に見えるようにする：生まれる（任せた瞬間）、届く（完了 → 成果物の列へ）、呼ばれる（出番が上に滑り込む）。いまの画面ではどれも観察できなかったので、実装の有無と「起きたときに見えるか」を監査の場面で動画で確かめる。

### 7. 漏れと小さなひっかかり

- 入力欄の `audit-lead` / `assistant` / `writer`、費用の `mock/assistant`：モデル名は子では隠す。根の会話では表示名にする。
- タイムラインの初期表示：骨組み（数行の薄い枠）を出す。
- 「<$0.01」の行は費用を出さない（§1.3 の「0 は出さない」の延長）。
- サイドバーのプロジェクト見出し「市場レポート」の下に「市場レポート」が 1 行だけ並ぶのは重複に見える。木が 1 本だけのプロジェクトは見出しを省く。

## 進め方の提案

1〜2 が構想の芯で、3〜4 がホームの主役の入れ替え、5〜6 が第一印象。全部を一度にやると前回と同じ「全部作り直し」になるので、**まず 2（任せた瞬間）と 3（チップの数字を減らす）を監査の場面で作って目で見る**のが、キラキラが戻るかを一番安く確かめられる。1 は Core Daemon 側（ホームの入力を受けるメタ LLM と、その権限）が要るので、2〜3 で手応えを見てから。

この文書は snapshot。方向が決まったら、`20261030_ui-redesign-spec.md` と同じ形の仕様を新しく書く。

## 追記：汎用性・プロジェクトの扱い・見た目の方向（同日）

### プロジェクトで分けていないか

コードで確認した。**切り替えで絞るしくみは存在しない。**

- ホームの `home.get` はプロジェクトを見ずに全部の木を返す。レーンの並びはデーモンの順で、プロジェクト混在のまま。
- サイドバーはプロジェクトが 2 つ以上あるときだけ見出しでまとめる（プロジェクトなしが先頭、見出しなし）。折りたたんで隠す機能はない。
- `useUi.projectId` は残っているが、使い道は「新しい会話の作業場所の既定」だけ（`Draft`・`HomeComposer`）。タイトルバーの切り替えは前回の作り直しで消えている。

つまり「日常のチャット・プロジェクト A の 5 人・プロジェクト B の 3 人」が同じホームに並ぶ。並列の把握という要件は満たしている。見た目の違和感として残るのは、サイドバーの見出し（木が 1 本しかないプロジェクトに見出しが付いて二重に見える）くらい。

### コーディング特化に見えないか

語彙（会話・エージェント・成果物・出番、採用・反映）は汎用で、diff・ブランチ・「変更」はコードの作業の子にしか出ない。監査の場面でも、コードの匂いがするのは「ログイン改善」のレーンだけだった。

ただし入口にコードが顔を出している。

- 空のホームと下書き画面の「作業場所」の 3 択（💬 / 📁 / ⑂）。初めての人が最初に見るアイコンに git の枝がある。
- サイドバーのプロジェクト見出しのアイコン（リポジトリ / フォルダ）。
- 「プロジェクト」という語自体が、開発寄りに聞こえる（内容は「作業のまとまり」）。

作業場所は「頼んだ内容から右腕が決めて、必要なら聞く」に寄せれば、入口から消せる（手がかり 1 と同じ方向）。

### 見た目：左ボーダー・角丸・透け

- **左ボーダー**：色つきの「左に帯」のカードは使っていない（出番・失敗のチップは枠全体に色）。縦線として `border-l` があるのは、サイドバーとメインの境、メインと成果物パネルの境、サイドバーの木の罫線（`TreeRow`）、引用の左線（`ChatStream`）の 4 か所。方針として禁止するなら、境は背景色の段差だけで分け、木の罫線は字下げと点だけにし、引用は背景の面で出す。
- **角丸**：トークンは 4 / 6 / 8 / 12px。使用は `rounded-sm`（6）73 か所、`rounded-md`（8、チップと出番の行）23 か所、`rounded-xs`（4）20 か所。控えめにするなら 2 / 3 / 4 / 6 に落とし、チップは 4、ボタンは 3、ポップオーバーは 6 くらい。
- **透け**：いまは不透明（`tauri.conf.json` の窓に `backgroundColor: #0b0c0e`、`transparent` なし、vibrancy の crate なし）。Tauri 2 では窓を `transparent: true` にし、Rust 側で `window-vibrancy` の `apply_acrylic`（デスクトップをぼかして透かす）か `apply_mica`（壁紙の色味だけ乗る。Windows 11）を当て、CSS の `--bg-app` / `--bg-canvas` を半透明にする。注意点：Windows 10 の acrylic は窓を動かすときにもたつく（Windows 11 なら問題ない）、ライトテーマでは透けた上の文字の対比が落ちるので面の不透明度を別に持つ、撮影（Playwright）には透けが写らないので目で確認する。透けを入れるなら、サイドバーとタイトルバーだけ透かしてメインは不透明に近づけるのが、読みやすさと「らしさ」の両立になる。

「一昔前の AI 感」の出どころは、暗い灰 3 段 + 細い枠線 + 6〜8px の角丸 + 小さな紫のアクセント、という組み合わせだと思う。枠線を減らして面の段差と透けで区切り、角を立て、アクセントを「生きている印」として動かす（手がかり 6）方向で、同じ骨組みのまま印象を変えられる。
