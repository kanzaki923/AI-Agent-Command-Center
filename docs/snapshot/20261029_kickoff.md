# 2026-10-29 キックオフ：進め方と初期判断

## ゴール

concept.md §12.1 の Vertical Slice（Tauri UI → Daemon → メタLLMがTask分解 → worktree 2つで並列実行 → 状況表示 → 成果物収集 → 統合・検証 → 人間が承認）を、手触りの良い UI 込みで一通り動かす。

## 初期判断

| 項目 | 判断 | 理由 |
|---|---|---|
| Daemon ランタイム | Node.js 22 | Bun 未導入。Claude Agent SDK が Node 前提。`node:sqlite` が標準で使える |
| DB | SQLite（`node:sqlite` 優先、問題があれば better-sqlite3） | ネイティブビルド不要にしたい |
| 通信 | 127.0.0.1 の WebSocket 上の JSON-RPC 風 + トークン | UI / CLI / テストが同じ経路。ブラウザの任意ページからの操作を防ぐ |
| モノレポ | pnpm workspace、内部パッケージは TS ソース直 export | ビルド工程を最小にする |
| API 契約 | `@acc/protocol` に zod で一元定義 | UI・CLI・LLMツール生成が同じ定義を使う |
| LLM ツール | API メソッド定義から自動生成し Capability で絞る | 「人間と LLM が同じ操作基盤を共有する」をアーキテクチャで担保 |
| オフライン動作 | mock LLM プロバイダ / mock Agent Runtime を最初から用意 | キーなしでデモ・テスト・E2E を回すため |
| Orchestrator の監督 | `task.wait` ツールで Run 内に待機し、完了イベントで再開 | 1 Run 内でコンテキストを保ったまま監督できる最小構成 |
| 作業ブランチ | `vertical-slice` | main を直接汚さない |

## 進め方

オーケストレーター（わたし）は設計と統合判断に集中し、実装はワークフロー上のエージェントに振る。

1. 基盤（モノレポ・protocol・client・daemon core・CLI 骨格）＋並行して調査（Agent SDK / Tauri シェル / UI デザイン言語）
2. 並列モジュール実装（LLM・ランタイム・worktree・統合・Policy/Budget・UI）
3. 結線して Vertical Slice を通す、E2E、レビュー
4. 手触りの磨き込み、引き継ぎ資料
