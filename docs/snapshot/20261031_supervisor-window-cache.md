# 履歴の窓と実行をまたいだキャッシュ（2026-10-31、本物の Anthropic API）

指揮役の履歴の窓（直近 40 件）を超えたあと、プロンプトキャッシュが効いているかを本物で測った。原因を切り分けるうちに、直接接続ではもともと実行をまたいだキャッシュが効いていないことも分かった。費用はこの調査全体で約 $0.2（`20261031_real-anthropic-cache-check.md` の分は除く）。

## 1. 1 件ずつずれる窓は、毎回キャッシュを外す

- 指揮役は「最初の依頼＋直近 40 件」を送っていた（`history.slice(-40)`）。40 件を超えると、実行のたびに一番古い発言が押し出され、先頭近くが毎回変わる。
- Haiku 5.5・直接接続、1 実行ごとに 2 件増やして 5 回：毎回、読み 約 1,000（tools＋役割）／書き 約 3,700。履歴はまったく読まれていない。

## 2. メッセージの途中で書いたキャッシュは、そこで終わる形では読めない

- 半分ずつまとめて切る案に変えても、読みは 約 1,000 のままだった。先頭は変わっていないのに。
- 印を手で置いて、生の Messages API で比べた（Haiku 5.5）：

| 1 回目 | 2 回目 | 2 回目の読み |
|---|---|---|
| 最後の発言 h20 で終わる | h21・h22 が続く | 全部（2,091） |
| h20 の後ろに状況の文（同じメッセージ） | h21・h22 が続く | tools＋役割だけ（817） |
| 同上 | 同上、h20 にも印 | tools＋役割だけ（821） |
| 同上 | h20 で終わる（同じ文、印あり） | tools＋役割だけ（820） |
| 同上 | h20 の後ろに別の状況の文 | 全部（2,089） |

- **同じ文でも、メッセージの途中とメッセージの終わりは、キャッシュの上では別物**。20 ブロックのさかのぼりも、この違いは越えない。
- 直接接続は、実行ごとの状況を `[アプリから]` の user の文として送っていた。API は続く user の発言をひとつにまとめるので、状況は最後の発言と同じメッセージに入る。次の実行ではその発言のあとに assistant が続き、メッセージがそこで終わる。だから、**実行をまたいだ履歴のキャッシュは、チャット・右腕・指揮役のどれでも効いていなかった**。
- LiteLLM 経由で、途中の system に対応するモデルは、状況が別の `role: system` のメッセージになるので効いていた（`20261031_real-anthropic-cache-check.md` の C）。

## 3. 途中の `role: system` を受け付けるモデル（直接接続）

| モデル | 受け付けるか | 次の実行の読み |
|---|---|---|
| Haiku 5.5 | ○ | 全部 |
| Sonnet 5 | ○ | 全部 |
| Sonnet 5.5 | ○ | 全部（5 秒以上あけたとき） |
| Opus 5.5 | ○ | 全部（20 秒あけたとき） |
| Haiku 4.5 | 400 `role 'system' is not supported on this model` | — |

- 書いたキャッシュが使えるようになるまで、時間がかかることがある。Sonnet 5.5 はすぐ次だと読めず、5 秒あければ読めた。Opus 5.5 は、同じリクエストを 5 秒後に送っても読めず、20 秒後なら読めた。実際の実行と実行の間はもっと空くので、問題にしない。
- 資料には Haiku 5.5・Sonnet 5 が載っていないが、本物は受け付けた。

## 4. 直したあと（本物、新しいコードを通して）

- 状況は、受け付けるモデルには `role: system` で送る。実行をまたぐ印は、最後の後ろのシステムメッセージの前に置く。窓は上限の半分ずつまとめて切る。
- Haiku 5.5 と Sonnet 5.5、1 実行ごとに 2 件増やす。途中に再開の通知（system）があり、1 回はツールループの 2 回目も入れた：

| 実行 | 読み | 書き |
|---|---:|---:|
| 41 件 | — | 約 3,050 |
| 43〜49 件 | 前回まで全部（3,050〜3,590） | 約 180（新しい 1 往復） |
| ツールループの 2 回目 | 3,408 | 52 |
| 61 件（区切り） | 約 1,000 | 約 2,030 |

- 400 は 1 回も出なかった（user の後ろの通知も、ツールの往復の途中の状況も `role: system` のまま）。assistant の後ろの通知は API が許さないので、user の文として送る（テストで確認。本物では試していない）。
- まとめて切ると、外れるのは区切りの直後の 1 回だけ。窓 40 件なら 20 件に 1 回。
