## 最後の QA で直したこと

画面を実際に操作して見つけたもの。

1. **失敗の出番が理由を言っていなかった**：「「配信リストの整理」が失敗しました」は会話のチップと同じことの繰り返し。題を失敗の理由の 1 行目にした（理由がないときだけ従来の言い方）。題と同じだけの詳細は `›` を出さない。
2. **予算のメーターと「使い切りました」が食い違った**：$3.03 / $3.40 なのに上限の出番が出る。子に渡したまま使っていない分が数えられていなかった。木の予算のメーターに、その分を薄い帯で足し、色もそれを含めて決める（`HomeTree.spend.committedUsd`）。出番の言い方は「予算（$3.40）の上限に達しました」に、詳細は子に渡した額も言う。
3. **ホームから送った会話の答えに気づけなかった**：送るとホームに留まるので、答えが届いて落ち着いた会話は下の薄い行に沈んでいた。最後に見たあとに待機・完了になった根の会話には、題を明るくして accent の点（未読）を出す。サイドバーとホームの両方。開くと消える。

4. **テストが一時フォルダを残していた**：デーモンを自分で閉じるテスト 5 本が `close()` を呼んでいて、テスト用の一時 ACC_HOME（`acc-test-*`）が実行のたびに残っていた。`cleanup()` に直し、デーモンのテストを 1 回流しても増えないことを確かめた。それまでに溜まった約 1,000 個は OS の一時フォルダに残っている（消すのは手で）。

## 残っていること

- 競合の解消役の会話が、元の木の下ではなくトップレベルに出る。親につなぐと、監督役の親が子の報告で起きて LLM を使うので、つなぎ方を決めてから直す。
- 古い orchestrator 経路の決定文に「Task」が残る（タイムラインの「詳細」でだけ見える）。使われていない `grantOrchestrator` / `ORCHESTRATOR_GRANT_METHODS`、`model/integration.ts` の一部も残っている。
- 設定で日次上限を上げても、日次上限で止まった作業は再開しない（出番の「上限を上げる」は再開する）。
- 出番を「終える」で閉じた失敗の子は待機に見える。
- 土台の既知の穴（`20261029_redesign-spec.md` §7）：readRoots を Claude の additionalDirectories に渡していない、起床の再試行タイマーがメモリだけ、シェルが書いたファイルは成果物にならない、モックの費用は推定、など。
- 本物の LLM での通しはまだ。監督役が実際に子を作るかは、モックの台本でしか確かめていない。
